# CADET application service core

`service::Service` is a caller-storage ordinary CLIENT IPC owner, separate from
the native client SDK, peer channel, tunnel and connection owners. It creates no
socket, allocator, task or private wire protocol.

## accepted MQ and native output protocol

`Service::new(instance, local_peer, clients, ports, channels, messages, limits)` borrows finite storage. `attach()` is called only after an application socket/MQ was accepted. It returns the original private branded `Client` generation; there is no Init or Connect packet. `receive(client, Request)` processes that exact original input. Protocol/policy errors are explicit `Result`; the native listener retains the original input for temporary table Capacity or closes its physical source for permanent bad-client violations. Valid late unknown DATA/destroy/receive_done is ignored. `progress()` binds one own-peer opening channel to a currently registered listener.

Before preparing output, reserve the final immutable native frame object and any queue metadata, using `next_output_len(client)`. Call `prepare_output(client, final_frame_bytes)` only after all such fallible native allocation/admission preflights succeed. It encodes the exact official ordinary IPC frame and returns `Prepared` with `Output` and borrowed bytes. Freeze and retain those exact bytes externally; the shared source pool may already be reused after the copy. There is one pending original output per MQ. A cancelled waiting future is not cancellation of that output. Retain a temporarily unqueued original frame or physically stop/detach the original MQ; never regenerate or route it to another MQ. Call `exposed(original_output)` only on positive physical output and `written(original_output)` only on a complete original frame write. Local send credit becomes usable only at written ACK. Native DATA write releases the sender's local retention, while the receiver still separately owes application receive_done. Neither fact claims remote application processing.

The channel table keeps an endpoint while a frozen old control for its raw local number remains pending on the same MQ, preventing that number from being reused before the old frame settles. The pending token itself preserves the old channel generation even if the source later closes. Stop the original socket/read/write cursors before `detach(original_client)`. `Loss` preserves its original pending output and exposed state; all owned ports revoke, loop partners receive destroy intents, dispatched remote opens get explicit cancellation intents, and remote bindings get explicit close work. No channel or payload is replayed to a new MQ.

## Shared bounded memory and liveness

`ClientSlot`, `PortSlot`, `ChannelSlot` contain metadata only. Each `ChannelSlot` has four small Tx records but no payload array or Vec. Payload buffers are one shared `MessageSlot` pool. The first `clients.len()` buffers reserve one ingress staging slot per MQ and must each fit `remote_payload_bytes`; a blocked MQ cannot monopolize every remote receiver. Remaining buffers share source credit reservations and retained source data. At least `channels.len()` of those buffers must fit `max(loop_payload_bytes, remote_payload_bytes)`. Reservation leaves one baseline maximum-capacity slot available per unfunded possible endpoint, and shares all surplus capacity up to window four. One idle endpoint therefore cannot consume the last usable credit buffer needed by a new endpoint.

Each local credit reserves a fitting shared buffer before its ACK can be written. A legally credited source DATA can always reuse its original reservation, without an unexpected buffer Capacity after application acceptance. Loopback encoding or peer admission frees the original shared buffer; credit is replenished only after the destination frame write or the peer channel ACK respectively. Complete-message payloads stay retained until a external owner has copied them. `message_bytes(message)` permits an exact still-retained source preview with stale pool-generation rejection.

Defaults are window four, local loopback full string 65523 bytes, remote whole payload 64348 bytes. Constructor bounds and peer `send_capacity()` produce a permanent transportable payload limit before any ACK grant. Native tunnel/CORE composition must additionally preflight its encrypted/CORE framing bound before accepting an open as usable, and configure the peer/service payload policy accordingly. There is no private fragmentation header or tail truncation. A credited over-bound remote whole string is explicit `Rejected { TooLarge }` plus channel retirement, not endless resource Pending. The ordinary official IPC inner message validator still caps each individual inner message at 64348 bytes. A valid empty C2S string represents zero messages, consumes/recycles only its source reservation and produces `Event::Empty`, not a fabricated peer or application delivery.

## Local application behavior

Outgoing application IDs are at least 0x80000000; incoming IDs begin at zero and advance monotonically without reuse on the same accepted MQ. Wire IDs are never Rust owner authority. Multiple clients may register the same hash; a duplicate within one client is refused, and only the owning client may close a registration. Closing a port leaves already bound channels intact. New own-peer requests wait for a listener and use two local channel endpoints, including when both endpoints share one physical MQ. Incoming announcement must actually finish writing before that endpoint receives credit or DATA.

Full validated inner-message strings are preserved byte-for-byte in local and remote service payloads. The current official public C CLIENT API injects only the first inner message into its application callbacks; preserving a full string at the service wire layer does not claim that C application callbacks consume a concatenated tail. Creation options are ignored and emitted as zero, matching current official application behavior. No custom private options mask is invented.

## peer port composition

Foreign peer lifetimes are held by the external coordinator through private `Binding`, `Admitted`, and `PeerDelivery` capabilities, not stored inside recyclable local metadata.

1. `next_open()` dispatches an original `Open` but grants no credit. The coordinator allocates a monotonically fresh raw peer CTN in the existing tunnel, establishes an actual `peer::ChannelOwner`, and drives tunnel/connection outputs. Only `peer_opened(open, &mut actual_owner)` can bind it after Ready and exact local/expected remote/port/direction checks. The one-time `claim_application()` prevents reassigning a used owner. `accept_peer(&mut actual_listener_owner)` likewise requires a Ready listener plus a currently registered port and creates an low-half application endpoint. Unknown ports remain a coordinator policy/close decision, never a success stub.
2. `next_send()` returns a borrowed original complete payload and opaque effect. Use `effect.channel()` to choose the original external Binding. Preflight and perform the fallible `owner.queue_send(payload, now)` copy, then `send_admitted(effect,binding,&owner,original_send)`. It verifies that exact owner's private claim, exact original source payload bytes, scope, and previously unassociated original send serial. Only then is the service buffer freed. `send_completed(admitted,&owner)` queries that exact retained peer send's completion; a caller-constructed outcome is not evidence. PeerAccepted replenishes only source IPC credit and does not prove remote application processing. Exposed but unacknowledged sends keep their original outcomes in the peer owner, including if the app has already closed.
3. `receive_peer(binding,&mut owner)` checks the ready binding, validates/copies the next in-order payload into that MQ's reserved ingress buffer, then calls `owner.deliver(original_received)`. Retain its `PeerDelivery` externally. Only a fully written local DATA followed by that application's receive_done produces `next_receive_done()`. `peer_receive_done(effect,original_delivery,&mut owner)` releases only the original peer handoff. Early/duplicate app ACK is ignored; callback replay is rejected.
4. Application teardown produces `next_close()`. Close/retire the original peer owner and settle or retire every original physical attempt first; `peer_closed(close,binding,&owner)` requires its Closed state with no pending original attempt before releasing binding metadata. Actual backend loss is `peer_lost(binding,&closed_owner)` followed by that same close path. A dispatched but not bound open remains in `canceling_open()` until its original external work actually stops, then `open_failed(open)` retires it. No default success substitutes for external peer work.

Private Rust generations prevent stale local callbacks only. They do not permit reusing old raw CTNs in one logical tunnel: the coordinator must continue the existing peer `Numbers` allocator. Only a true new tunnel/key namespace after old crypto/skipped keys/ports have retired can reset that wire namespace. This service does not add restart or clear that obligation.

## Host interfaces

Four focused models cover complete loopback strings with actual-write credit versus application receive_done, same-MQ two-namespace forward/reverse flow under a minimal shared pool, original accepted-source loss and no incoming-ID reuse, and peer opening/send claim/peer ACK/local receive_done/close effects. The loopback model also covers old pending control frames preventing premature same-MQ high-half ID reuse.

This module is a working bounded application service owner. A native listener, peer/tunnel/connection coordinator, persisted origin monotime and automatic CORE/DHT discovery are distinct explicit composition work. Monitoring IPC requests are `Unsupported` here; this module does not fabricate monitor END rows. Existing independent inspector CLIENT code and official wire codecs are separate. The native endpoint must expose service monitoring from coordinator state when implementing that native endpoint. No hidden scheduler, listener, resolver, thread, FFI success path or stopped-branch implementation was created.
