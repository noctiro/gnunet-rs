# BLOCK foundation

This workspace package targets GNUnet v0.29.1 revision `346358e26d4dcc2dc4f51bef5d52dca29c7d8165`. It is not an owner completion report. `inventory.json` binds the exact source inputs and separates the 15 public functions, public callback/type surface, nine installed plugins (12 concrete types), inactive contrib modules, and the 17 declared block numbers. No production C FFI, OS loader, implicit time, allocator, or new wire encoding is used.

The default installed plugin set is TEST, DHT HELLO, FS (DBLOCK, IBLOCK, UBLOCK), GNS, DNS, REGEX (state and accept), REVOCATION, SETI_TEST and SETU_TEST. REVOCATION exists only if both official configuration values can be read. The configuration adapter supplies its already parsed/narrowed WORKBITS and EPOCH_DURATION snapshot; context construction does not pretend that absent values configure an active plugin. SET_TEST24/CONSENSUS25 live in `src/contrib`, outside the current plugin Meson chain; template is built but explicitly not installed. Their enum constants remain available and custom Rust plugins can own such numbers. These distinctions are profile inventory, not claims that a future feature was implemented by returning Unsupported.

## Ownership and API representation

`plugins::Context` borrows a stateless builtin registry in the selected load order. `callbacks::CallbackContext<P,N>` owns a fixed array of arbitrary pure Rust plugin objects, exposes all declared callback operations, and drops the objects on context destruction. A caller enum can combine different implementations without heap allocation. `PluginFunctions::Creation` replaces plugin-specific C varargs with typed values; builtin options are `SeenSet`, `FilterBytes` and the unknown-guard fallback. Explicit finite type slices replace unbounded sentinel scans, while an encountered ANY still terminates lookup. First match wins. No callback is synthesized when a type is absent.

A custom plugin's Creation<'a>, optional raw input and group associated type explicitly share the retained caller/context lifetime; `GroupState` expresses optional serialization, mark-seen and merge callbacks. `MarkSeen` preserves the source void callback: the public wrapper can return YES or SYSERR, never a fabricated callback return. Rust `Drop` implements group/plugin closure destruction. The callback-family type prevents arbitrary C function-pointer casts. `group_merge` consumes the right owner even on NO or a safe Rust merge error; the source's missing-left-merge-callback exception returns the right owner in `MergeOutcome::Unsupported`. A NULL right succeeds; NULL left consumes the right. Positive/compile-fail examples verify that a live group cannot be used after its context is destroyed. An additional compiler fixture constructs and runs two groups retaining distinct caller Tags, then requires E0505 for premature Tag, context, storage or raw-owner moves. The builtin copying Context keeps its independent raw-input lifetime, verified by releasing the original serialized owner before using the restored group. Raw ABI layout, `void *`, dynamic shared-library entry symbols and plugin unload names are replaced by these explicit Rust ownership operations; they are not advertised as C ABI compatibility.

## Bytes, work, clocks and explicit profiles

Bloom state is exactly native-endian nonce32 followed by bit bytes, with no magic/header. Mingle hashes exactly the input64 and native nonce32. Both endiannesses are explicit; native oracle runs on this machine's little-endian profile, while pure tests check the big-endian preimage. The container draws 32-bit big-endian words from SHA512, uses modulo bytes*8 and LSB bit numbering, and hashes the previous 64 bytes after every16 words. Unsigned32 size multiplication wraps before division and the original min8/max32768/early entry cap is retained. Imported raw shorter than4 fails before modifying storage; length mismatch keeps its nonce and resets the filter. Zero-size or k0 groups retain the source NULL internal filter behavior, which differs from a NULL group. Signed-int conversion for k>INT32_MAX records this compiler's two's-complement native profile.

A caller supplies `fresh_nonce`, sampled with the native random_u32(UINT32_MAX) contract when there is no imported state; nonce generation is an explicit entropy boundary, not a constant RNG or implicit filesystem operation. Imported nonce can contain any u32, including UINT32_MAX. Capacity failures are Rust resource errors and preserve output; scratch may be changed where documented. Serialization writes no prefix before capacity validation. Work and output storage stay caller-owned and no durable storage claim is involved.

Clock is read at the source operation readpoints. DNS/REGEX accept reject strictly past expiry and do not turn a bad purpose/size into a clock read. Reply validation does not repeat signature/expiry checks except the DHT HELLO parser's own behavior. HELLO scratch limits and the exact metadata-only versus conditional deterministic address-signing profile are explicit; failure never tries a weaker profile. C/R UTC comparison uses stable expired/NEVER/one-day values. Exact equality, saturation and read-count boundaries are separate pure Rust source-derived witnesses; they are not passed off as injected normal C clock observations.

REV uses signatures, sorted32 BE nonce values, raw BE timestamp plus serialized type+public36, and 32 Argon2id13 hashes with salt16 `GnsRevocationPow` (no NUL), t3/m1024KiB/p1/output64. The score is integer average leading-zero bits, epochs=(score-difficulty+1), lifetime saturates and adds epoch/10; transmitted TTL is informational. Timestamp NEVER is not-yet-valid. Expiration NEVER avoids an unnecessary second clock read, matching get_remaining. Both PKEY and EDKEY paths have C-built and Rust-built signed proofs; no caller validation trait substitutes for installed revocation functionality.

Shared `gnunet-crypto/pow` owns the sole RustCrypto argon2 implementation (exactly0.6.0, defaults disabled, zeroize enabled); BLOCK re-exports that module. It uses 1024 caller-owned 1KiB aligned blocks. Its necessary additions are blake2 0.11.0 and base64ct 1.8.3, locked with archive checksums. Public PoW is a public-work primitive, not a password API: scratch persists/reuses under the caller's ownership; no claim of whole-memory erasure is made. Temporary output is erased and final output changes only on success. No registry alloc/std/getrandom/password-hash feature is enabled. The workspace policy includes the BLOCK target and its exact dependency contract. Fresh integrated proof remains required.

## Defined C quirks and safe rejections

GNS get_key ignores the helper status and returns YES with output untouched for an unknown key type. Its checker permits trailing bytes past the advertised size, while reply hashing includes all supplied bytes. Zero-byte EDKEY payload verification is preserved even though an independently authenticated encrypted record normally needs a tag. GNS payload >UINT16_MAX makes the normal helper abort at gnsrecord_crypto.c:431; Rust returns TooLarge. This is not support for larger blocks. The initial oversize oracle abort is preserved as a failed exploration and is excluded from normal-success paired comparisons; the upper accepted size65535 remains tested.

REGEX get_key validates the fixed prefix only; token totals and destination indices are not silently strengthened in its key API. Accepting flag exactly1 with NULL/empty xquery returns early even with trailing bytes. A present CString remains distinct from NULL. Non-accepting iteration checks exact total token bytes. C's out-of-range destination pointer and short revocation-signature reads are safely rejected rather than executed as UB. C reply assertions (bad GNS shape, REGEX accept size, invalid SET marker, key mismatch) become explicit Malformed errors. Active-left/NULL-right Bloom OR is a C null dereference and becomes InvalidInput; the defined inactive-left path remains supported.

These cases need explicit acceptance review. They do not waive normal installed-plugin functionality or declare the DHT/FS/GNS/DNS/REGEX/REVOCATION services complete. No owner/catalog status is changed by this implementation.

## Limitations

The package uses workspace inheritance, a single package identity, SDK exposure and explicit architecture/no-allocation requirements. The current source still requires a fresh integrated verifier and final whole-owner review; a candidate receipt is not an acceptance of later workspace edits. Final receipts must be freshly bound after the final tool/source freeze. Cross-architecture runtime and dynamic native DLL ABI behavior are not claimed by the little-endian normal C and embedded compile witnesses.

The integrated source widens FS and REV advertised-length additions before comparison. On a32-bit target, the C unsigned additions can wrap only below their already-required minimum block sizes and still reject; Rust must return the same negative result without a checked-arithmetic panic. Six maximum-header normal C/Rust cases and a separate public Rust regression cover the rejected bytes. Embedded target checks compile this path; no actual32-bit C runtime observation is implied.
