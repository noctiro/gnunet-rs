# GNUnet native IDNA profiles

Pure Rust, `no_std`, no allocation, `forbid(unsafe_code)`. Production depends only on the `gnunet-dns` trait. No registry dependency, FFI, locale state, filesystem or DNS access is involved. This package supplies the native text backend; its finite profile proof grants no whole DNS service status.

`Backend::new(&mut Workspace, Limits, NativeProfile)` implements the complete DNS text backend. `NativeProfile::Libunistring1_5Unicode18_0` corresponds to the normal reference: libidn2 2.3.8 with its Unicode15.1 TR46/IDNA2008 tables, linked to libunistring1.5 Unicode18.0 properties/NFC. `NativeProfile::Unicode15_1` fixes all properties and NFC to15.1; it has official data/normalization coverage, but is **not** a second independently built C runtime profile. Profile choice is explicit. The currently built C runtime verifies the first profile only.

ToASCII is GNUnet's nontransitional flags25 path (NFC1 | NONTRANSITIONAL8 | unused compatibility ALLOW_UNASSIGNED16). It applies the complete pinned TR46 mapping, NFC, A-label decode/check/roundtrip, IDNA2008 derived validity, ContextJ and native per-label Bidi behavior, with STD3 disabled. In particular, modern Unicode assignments and emoji cannot bypass the fixed lookup tables. Plain ASCII punctuation that the C profile permits remains permitted. ToUnicode flags16 is independently implemented: Punycode/UTF8 decoding, unchanged ordinary label case/NFC, no IDNA validation. Its malformed-label result permits the parser's native raw fallback; resource, capacity and work-borrow failures never permit fallback.

The C lookup path recognizes each ContextO rule identifier but does not execute the ContextO conditions. Its Bidi helper also permits EN/AN mixing and considers a final NSM after punctuation a valid ending. These are preserved in native lookup. `validate_idna2008_label` is a separate, explicit stricter NFC Unicode15.1 label validator implementing RFC5892 ContextJ/ContextO and RFC5893 constraints. Its caller supplies whether another label makes the complete domain a Bidi domain; it is not a complete automatic domain-validation interface.

Native IDNA writes stage in the caller's `Workspace`; the separate NFC helper completely validates scalar values and caller capacity before committing. All public writers preserve the complete output slice on error. Scratch size is exactly **6352bytes**, independent of input size. The byte ceiling is explicit (`Limits::GNUNET=65535`). Native ToASCII permits fewer than255 mapped scalars before normalization. Maximum canonical expansion is4, so1016 scalars suffice; A-label normalization needs at most4×63=252 scratch scalars. Native ASCII output is at most253 bytes without a final root dot,254 with it. ToUnicode permits255 total scalars, each label≤63, at most1020 UTF8 bytes. The NFC helper accepts at most254 input scalars and permits up to4064 output bytes in caller storage, including full-composition exclusions. Table searches are logarithmic; canonical sorting is bounded by1016² moves and Punycode by254² scalar work on an input that will subsequently fail DNS width if oversized. Punycode decoding has no extra temporary input array or allocation.

Input is an explicit UTF8 byte slice **without** a C terminator. Interior NUL is refused; callers holding C-string storage should pass its value before the terminator. The DNS parser separately preserves wire-label NUL octets, and its native-text writer applies the native C-string truncation before this backend. UTF8 and Punycode failures are safe errors. `Error::Native(i32)` is a diagnostic category, not a C ABI/error-priority compatibility promise; the DNS adapter maps every such error to `Malformed`.

`tools/compare.py` exercises the normal C libraries, not extracted functions or shims. It compares accepted/rejected state and successful bytes. All different diagnostic codes remain visible in receipts. The deterministic random Punycode corpus has18 differences involving low surrogates that C's Punycode decoder accepts internally and its NFC subsequently changes; both complete APIs refuse them. Rust does not manufacture invalid UTF8 or surrogate characters.

The existing55 normal-C DNS check/builder observations execute through the new backend.53 agree directly. Two existing safe parser boundaries are explicit: a byte slice with an interior NUL is refused, and Rust accepts the exact1-byte root wire size where C's low-level root builder unnecessarily requires2bytes. Other153-row parser classifications (CERT/URI/DNAME corrections, atomic failures and ownership) remain unchanged; this backend does not silently promote those rows.

Reproduction requires the fixed official archives listed in `data/provenance.json`, extracted libidn2 source, and an unchanged normal GNUnet utility library/build. No C library is rebuilt or changed. The generator requires explicit `--libidn2-source`, `--ucd15` and `--ucd18`, plus either `--check` (read-only) or `--output EXTERNAL-STAGING` (review generated files before copying). It never writes directly into this source directory.

`verify.py` requires explicit `--gnunet-source`, `--reference-build`, `--reference-library`, `--idn2-library`, `--unistring-library`, `--libidn2-source`, `--libidn2-archive`, `--libunistring-archive`, `--ucd15`, `--ucd18` and `--output`. The output directory must be new and disjoint from source. Every Cargo target, compiled probe and receipt goes there. The probe compiler reads the reference build's Meson `compile_commands.json`, checks that its DNSPARSER unit points at the pinned source, and preserves the flags. No fixed host or temporary path is embedded in these tools.

An additional `parsed_label` relationship case calls C `GNUNET_DNSPARSER_parse_name` on `\x0dxn--bcher-kva\0` and compares both consumed offset15 and Unicode `bücher` to Rust `Reader.name` followed by `Name.write_native_text(&Backend)`. It is separate from the55 frontend observations and does not relabel the original153-row corpus. See `UPSTREAM.md` for exact sources and semantic boundaries.

`examples/native_pack_probe.rs`, then executes3846 fresh normal-C/Rust boundary
comparisons and eight native graph/prefix regressions. This distinguishes raw
wire preservation from native IDNA canonicalization, conservative builder capacity
from wire size, and semantic NO/TC from resource failure. Only the known
native i−1 count bug is projected to emitted counts in those fixtures. All65536 native flag words and65536 fixed header patterns are compared separately,
