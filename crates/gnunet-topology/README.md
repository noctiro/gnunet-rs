# TOPOLOGY pure policy

Default `no_std`/noalloc code exposes finite `Limits` and `VerifiedFrame`. The optional `alloc` engine uses a caller-owned `Rc` allocation domain and checked serials, with no implicit Atomic64/platform requirement. All clock samples, connection/source observations and native effect receipts are explicit inputs. No I/O, task, storage, entropy, key acquisition, or deduplication hash exists here.

`VerifiedFrame::verify` uses the existing `gnunet-hello` parser and actual `verify_at` to tie the full original HELLO_URI bytes to a private verification receipt. It performs signature work when called in production. A structural parser result or caller boolean cannot construct this wrapper. The selected profile is explicit; Reference029 authenticates metadata only and never grants address validation or connection authority. HELLOs without addresses or already expired at admission are not propagated. Accepted original frames are copied under aggregate/per-frame quotas; forwarding preserves the complete original message, including its original reserved/count bytes.

The alloc engine keeps a bounded peer table and one suppression bit per source/recipient pair within the source's four-hour HELLO window. The default64-row table uses512 bytes for these bits; the1024-row maximum uses128KiB. It never sends a peer its own HELLO, maintains a five-minute spacing per recipient, and rotates recipients/sources fairly. Byte-identical duplicate HELLOs keep suppression. A newer-expiration or larger-address-set accepted update changes only that source's revision and clears that source's bits. A late whole write for an old revision cannot suppress the replacement. Old in-flight immutable sends retain their original revision, node allocation and connection generation. A source row cannot be evicted while another row owns an original send referencing it. Expiration removes cached bytes without moving a pending packet or inventing a native completion. Deadline selection scans peer rows rather than a timestamp matrix.

`advertisement` and `control` prepare immutable effects without changing business state. Only native admission calls `gossip_queued`/`control_queued`. `gossip_finished` accepts the original effect plus full CORE payload status, which proves no remote delivery. `control_written` means the original cancellation/suggestion bytes were wholly locally written, never that TRANSPORT connected. At less than the target connection count, known peers receive strength1 and existing connections strength2. Strength is local policy only: official wire hints use best-effort priority1 and bandwidth0. An unchanged hint is left intact, preserving TRANSPORT's retry state. Current addresses are discovered/validated by TRANSPORT, including known disconnected neighbours with no local HELLO. Reconsideration is once per minute unless a identity/connection/HELLO event changes policy earlier.

The native adapter supplies exact physical loss before `controls_retired`/`connections_lost`. Any subsequent action is a distinct fresh policy intent; old operations are not rebound or replayed. Two pure metadata models cover unchanged hints, fresh intent after mock source retirement, and revision/window suppression. They passed during integration using public mock IDs, without cryptography, I/O or provider verification credit. Native operation and official interoperability remain unverified.
