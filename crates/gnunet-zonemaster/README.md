# ZONEMASTER material and bounded scheduling core

This crate prepares official GNS record blocks and owns the bounded publication scheduler. Its `alloc` preparation/scheduling profile requires an allocator and native 64-bit atomics, as used by its existing owner identity counters. The native `gnunet-zonemaster-host` composes NAMESTORE monitoring and inventory, durable expiration allocation, Rust encryption/signing, NAMECACHE, DHT, PROGRAM, SERVICE and STATISTICS.

`material::prepare` consumes the original NAMESTORE authority, canonical case-preserving NFC label, checked records and full-set expiration. The caller explicitly chooses `Destinations::PublicOnly` or `PublicAndLocal`. Both validate the original authoritative records and build the `OMIT_PRIVATE` public projection; only `PublicAndLocal` normalizes and serializes the complete local view. Relative expirations convert once at the coherent source time. With NAMECACHE disabled, only public record lifetimes guide refresh and publication; an unused full-set expiration does not constrain the public projection. Empty/deleted events and public-only inputs with no retained public records return None through the original source revision/supersession path, without a worker origin, query derivation, nonce reservation or signature. They invent no DHT erase or completion receipt. Keys, labels and plaintext have zeroizing ownership and redacted Debug output.

`Prepared::into_sealing` derives the official zone/label storage query and creates one `SealPlan`. The plan issues one `ExpirationRequest`, bound to its original material. `after(previous)` computes the official next value from the record-derived minimum and the checked prior highwater plus one. Missing history and an earlier value of zero are distinct. A production caller must durably consume `Expirations::maximum()` before passing that assignment to `SealPlan::seal`; the pure assignment itself proves no persistence. This crate performs no filesystem access and supplies no implicit process-local nonce ledger.

The public and local lanes share a ciphertext only when their complete final serialized RDATA matches, including flags, order and padding. Their shared assigned expiration satisfies both minima. Different RDATA allocates the public value first, then a strictly greater complete local value under the same official storage key, each at least its own minimum. NAMECACHE selects the greatest expiration for that key, so the paired public-only block cannot replace this local version and remove its still-valid private records. If the public floor is `u64::MAX`, a distinct later local value cannot be represented and sealing returns Overflow; shared identical RDATA may still use one final value. `PublicOnly` has no local output or unused local nonce: it can consume a public `u64::MAX` once when prior history permits, and any subsequent request under an already consumed MAX still returns Overflow. The individual records keep their original expirations and filtering, even when the enclosing local block is assigned a later value. The native host retains the highwater across restart and label deletion; cancellation or failure after reservation does not return consumed values. This ordering protects the paired version and all older public values tracked by that ledger. For a distinct set with retained live PRIVATE records and enabled NAMECACHE, `schedule::Core` admits the paired public lane only after the original CACHE operation receives its successful reply. Pending, refused, lost or expired cache work cannot authorize that PUT; a terminal cache failure retires the paired public lane. Routine republication therefore cannot expose a newer public block before its complete local partner has been accepted. Normal public-only or shared RDATA remains parallel, and disabling NAMECACHE retains public publication without claiming private local resolution. New authoritative data can supersede an older version. The dependency covers the publisher's selected NAMECACHE and cooperating publication chain; other publishers using a separate local cache, unknown copied-key history, deliberate cache deletion and volatile cache restart are outside this local processing guarantee.

sealing uses the existing typed PKEY/EDKEY primitives and official block format. `PublicPublication` contains only the checked public product; an actual `LocalCache` separately retains legal private records through `seal_for_namecache`. `Sealed::local()` returns Option: a public-only result has None, not a public projection relabeled as a complete local set. Prepared and Sealed report their destinations, and Core rejects a mode inconsistent with its cache configuration before native work. Public seal rejects PRIVATE, RELATIVE and MAINTENANCE; local seal still rejects unnormalized RELATIVE/MAINTENANCE. A DHT port accepts only `PublicPublication`. Assigned expirations flow into the signed block, cache product and DHT PUT TTL. Retained/transient resource accounting charges only selected inputs and output buffers, counting a shared allocation once; buffers erase on failure or drop. The SDK reexports this same explicit API through `gnunet::zonemaster` without a separate compatibility wrapper.

`schedule::Core` owns finite sources, label revisions, original job targets, worker states, both native lanes, cancellation debt and reclamation. Private source/job/material tokens, opaque constant-time authority equality and exact labels preserve original callback ownership. Inventory fences prevent older rows and workers from replacing later monitor events; lost sources supersede their jobs. Ordinary inventory keys stream beyond the active metadata capacity. Successful no-output submissions also collect unreferenced versions immediately while preserving live monitor/inventory fences and all job references; they do not depend on a nonexistent worker retirement to reclaim metadata. Monitor-fence pressure halts credit or retires the old iterator before restart.

Relative lifetimes shorten the full-zone refresh window to duration/4, capped by the configured official four-hour default. Finite targets are never renewed by late signing or a clock adjustment; minimum delays avoid zero-TTL busy loops. Public pacing retains the prior set count and fifteen-minute per-record ceiling. Native submission describes an local API/write boundary and supplies no remote DHT storage receipt. Running workers retain ownership until their return or join.

No new GNUnet wire format, IPC operation, C ABI or legacy compatibility path is introduced. Source authoring and formatting alone establish neither executed interoperability nor performance acceptance.
