# Official GNS record compatibility

Reference: GNUnet `v0.29.1`, commit
`346358e26d4dcc2dc4f51bef5d52dca29c7d8165`.

- `src/include/gnu_name_system_record_types.h`: official record type values.
- `src/include/gnunet_gnsrecord_lib.h`: flags, `GNUNET_GNSRECORD_Data`, and
  `GNUNET_GNSRECORD_MAX_BLOCK_SIZE` (63 KiB).
- `src/lib/gnsrecord/gnsrecord_serialization.c`: 16-byte network record,
  canonical size calculation, serialization and deserialization.
- `src/lib/gnsrecord/gnsrecord_misc.c`: `GNUNET_GNSRECORD_z2s` encodes the entire
  typed public key; no private `z1-` prefix is used.
- `src/include/gnunet_crypto_lib.h`, `src/lib/util/crypto_pkey.c`: typed PKEY/EDKEY
  bytes; raw curve bytes alone do not identify the algorithm.
- `src/lib/util/strings.c`: exact Crockford alphabet, accepted aliases, and
  unused-bit decoding behavior.

The record header is `expiration:u64 | data_size:u16 | flags:u16 | type:u32`,
all unsigned big endian. Expiration uses microseconds and its meaning is relative
only when flag `0x4000` is set. Flags and unknown type values survive serialization;
the resolver/publisher remains responsible for critical extensions, private data,
shadow selection, expiration conversion, value schemas, and signatures.

`serialized_len` implements the C reference's first-record rule: a first PKEY or
EDKEY bypasses power-of-two padding, even in a mixed set. An EDKEY in a later
position does not bypass padding. `serialize` uses that canonical size;
`serialize_to_size` mirrors the low-level C serializer's explicit destination size
and zero-fills its remainder. The 63-KiB encrypted-block cap is exposed separately
as `MAX_BLOCK_SIZE`, because low-level serialization also serves IPC.

`RecordSet::parse` takes an explicit count and maximum count. `parse_padded`
discovers the C all-zero-header sentinel but cannot distinguish a wholly zero
record header from padding. Both reject a nonzero padding suffix and return typed
errors for malformed inputs instead of the C count helper's ambiguous zero.
Record loops are bounded by the maximum count; checking the padding costs at most
the supplied byte length. Block/IPC owners must apply their input byte limits.

Zone text is exactly 58 characters for the 36-byte `typeBE32 || public_key32`.
The decoder matches the C implementation's lowercase and O/I/L/U aliases and its
ignored low two padding bits. The encoder produces uppercase canonical text.
PKEY and EDKEY are supported representations; the registered FAESTKEY record
codepoint is preserved, but no unsupported FAEST cryptography is advertised.
Decoding a zone key does not authenticate it or validate its curve point.

## Independent fixtures

The eight `.bin` fixtures in `tests/fixtures/` are generated by compiling the
**unmodified upstream C function bodies**, extracted from an explicit checkout.
A temporary minimal platform shim supplies byte-order and logging macros. The
upstream source bodies are not vendored into this crate and their AGPL license
notice is retained in the temporary translation unit. The Rust implementation
and Python orchestration are independently written.

Reproduce and verify without network or an installed libgnunet:

```sh
python3 crates/gnunet-gnsrecord/tests/upstream_oracle.py \
  --source /absolute/path/to/gnunet-v0.29.1
```

The script checks the upstream Git commit and SHA256 of every source input before
compilation; it verifies the checked-in fixture bytes by default. `--write` is an
explicit fixture regeneration action. Rust integration tests compare literal
header bytes and these independent fixtures, covering ordinary records, first
and non-first delegations, empty sets, flags, microseconds, and both typed zTLDs.

This crate implements the representation layer. It does not claim GNS resolver,
zone encryption/signing, revocation, or full-node interoperability completion.
