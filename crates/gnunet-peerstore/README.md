# Official PEERSTORE service core

This no_std crate owns the active GNUnet 0.29.1 STORE, ITERATE_START/NEXT/STOP and MONITOR_START/NEXT service protocol. Filters, client rows, operation rows and a shared immutable response-slab pool are all supplied by the caller. No allocator, scheduler, resolver, native socket, private wire or peer authentication is created.

The official wire codec is `gnunet_wire::official::peerstore`. Every numeric field is big endian; per-MQ u32 request ids are preserved. GNUNET_OK is 1 and SYSERR is -1. STORE option 1 is REPLACE; the pinned C backend treats other raw values as MULTIPLE. Iterators use an implicit first credit of one and subsequent rounds capped at 256. STOP reads the entire official u32 id. A monitor uses one MQ because MONITOR_NEXT has no request id; notifications use rid 0. Monitor initial enumeration reaches SYNC only from an successful end-of-scan. Live zero-credit updates are skipped, as in the active C handler, and NEXT does not replay them. There is no additional legacy WATCH command among the active registered handlers.

`Storage` is the explicit synchronous reference/in-process port. Native production uses `begin_store`/`complete_store` and `scan_request`/`scan_started`/`complete_scan` with an explicitly started bounded storage worker. STORE retains canonical original record bytes and rejects a completion for another record or source allocation. A scan reserves one original credit so a concurrent live notification cannot spend it. STOP/reuse/physical source loss makes old scan receipts stale. A queued or locally written record is never remote application consumption.

Native must report queue admission, positive writes and full original writes using the private Output token. Detach follows physical MQ retirement and preserves its original queued/exposed/pending storage metadata. Source close does not roll back a committed/in-flight backend write; an late commit may notify other live monitors without reviving its old source. Unknown storage outcomes emit no saved-success result.

The response pool needs at least one frame-sized slab per potential MQ. A source owns at most one pending response or retained STORE. The native bounded policy physically closes a monitor that exceeds this retained-output budget; it does not fabricate a SYNC, consume nonexistent credit or let that source block every other query. Fixed operation/filter limits may explicitly refuse a request. No per-iterator snapshot of the database is retained: scans advance monotonic backend UIDs, including changes while a round is paused.

Record peer identities and HELLO values are cache claims. Access derives only from IPC admission policy; neither a key name nor a claimed peer grants PILS signing authority or authenticates addresses. HELLO verification remains the consumer's explicit responsibility.
