# Official DV boxed-payload crypto material

Default noalloc, caller buffers and explicit entropy/identity/source/clock values. No IO, provider tasks, hidden RNG, private-key file, native/C dependency or crypto execution is introduced by source preparation. This is KEM/AEAD/signature production code, not a successful CryptoPort stub.

`Instance::source(local,now,until)` brands one caller-observed original source. Its checked Cell allocation counter permits bounded source-slot reuse while old Token values remain distinct; no global or implicit Atomic64 exists. Source::task(stamp,now,until) fixes one original task/expiry/source. The stamp is source-monotonic, not recipient UTC. `Source::retire` invalidates every retained task; expiry never extends. This pure constructor is not an attestation that a live MQ exists.

`Task::prepare_seal(target,now,entropy)` performs public EdDSA→X25519 conversion and official0x0020 DHKEM using the existing source-exact primitives, retains its erased32-byte secret, and draws fresh24-byte nonce from the explicit entropy capability. `PreparedSeal::region` is exact purpose30/80 bytes. `seal_local` uses an explicit caller-owned EdDSA key whose derived public equals the original source. `seal` independently verifies a external signature over the same fixed source/target/stamp/encapsulation. Both then construct104-byte sender/signature/stamp metadata, perform XChaCha20Poly1305 IETF detached encryption with empty AAD, and use the existing canonical86-byte DV BoxHeader. No extra KDF/domain/NUL/private wire exists. Secret material is consumed once on success or failure; no nonce/key material replay API is exposed. Output is atomic after full preflight; whole caller scratch is wiped on every return.

`Task::prepare_open` retains the exact original final-hop box. `RecipientKey::new` checks an already caller-owned X25519 scalar's derived public equals the conversion of the exact recipient EdDSA identity. `open_local` performs DHKEM. `open_with_shared_secret` is explicitly for a trusted original external provider and grants no independent provenance to its supplied32 bytes. Both perform AEAD tag verification, exact plaintext/inner-frame validation, nested DV rejection, and purpose30 sender signature verification for the fixed target/encapsulation. No plaintext is copied to output before all checks. `Opened` is a borrowed, redacted, zeroizing plaintext owner; `message(now)` rechecks the original source/task and Drop wipes the returned range. Metadata getters expose historical authenticated sender/stamp/token only.

No Opened or Sealed value grants replay, durable nonce/encapsulation/stamp, path validation, original Engine admission, native enqueue/write, or remote processing authority. Current DV route learning does not yet implement boxed-payload replay admission; that remains explicit unfinished integration work. The base one-shot path remains available. `cache` supplies bounded reusable sender/recipient material and fixed caller slots, documented below; no per-packet PILS signature is required on the cached path.

No crypto/key/entropy/model/compiler/Cargo/native/store/socket execution occurred. No vectors were imported/generated, and no private key fixture/file was read or hashed. Mixed-C crypto/packet interoperability is not claimed.

## Fixed reusable material

`PreparedSeal::certify`/`certify_local` independently verifies the original purpose30 signature once and consumes KEM material into `SendMaterial`. Its original source, target, encapsulation, signed epoch stamp and expiry remain immutable. Every new packet has a distinct original Task, must use that epoch stamp, must expire no later than its material epoch, and must belong to the exact original Source allocation. This matches the official cached-epoch payload stamp behavior; the stamp is not a per-packet wall-clock/replay verdict.

The24-byte nonce is the original fresh random16-byte prefix plus a checked64-bit counter seeded from the original remaining8 random bytes. Each attempted encryption burns a nonce, never wraps, and has an additional finite caller message budget(u32). Preflight failures do not burn a nonce or modify output; failures after encryption begins cannot reuse the nonce. Counter exhaustion/message exhaustion/expiry/source retirement require new explicit material. No entropy/signature job occurs per cached packet; AEAD still occurs per packet. No raw key getter, Clone, serialization or reset API permits rolling the nonce state back.

`ReceiveMaterial::local` performs matched local KEM. `from_shared_secret` remains an explicitly trusted provider port; the native companion only uses the original PILS Secret32. Recipient key/proof cache binds original local source/target/encapsulation and expiry. Every packet performs AEAD and exact plaintext checks. Only exact sender+stamp+signature bytes under the fixed target/encapsulation reuse a previous signature check; any changed statement is verified in full before replacing the private proof. Invalid tags/statements leave existing key/proof/expiry unchanged. No caller can construct SignatureProof or set it from persistence/unverified metadata.

`SendSlot`/`ReceiveSlot` are caller-provided fixed storage (e.g. core::array::from_fn). Cache constructors reject empty/nonfresh storage. Capacity cannot grow from attacker input; direct occupied-slot handles are constant-time, optional source/target/encapsulation find and reap are bounded linear scans. Install replaces only the caller's explicit index, validates new material before touching the old owner, and returns an original typed epoch handle. Stale handle revoke cannot remove a replacement. Replace/revoke/reap/clear/Cache Drop all drop and zeroize key owners; Drop also empties borrowed caller rows. Source loss can revoke/clear without accessing a failed clock. None of these operations acknowledges or cancels separate original provider/IO debt. Cache hits/packet processing never renew deadlines. Logical rollback before material creation/certification is refused; the surrounding owner still enforces the original immutable native hard target.

The cached receiver is cryptographic authentication only. Repeated valid nonce/ciphertext can still authenticate; the separate live replay owner below must reject it before Engine/application admission; persistent receipt integration remains absent. No cryptographic vector/benchmark/model/native/key/entropy execution or measured performance is claimed.

## Exact bounded live replay admission

`replay::Replay::new(&Source, &mut[PeerSlot], &mut[NonceSlot], Limits)` exclusively claims one caller-observed original local source. Only private-constructor `Opened` results can be supplied to `admit`; both one-shot and certified-cache opening retain their target, encapsulation and nonce after AEAD and signature validation. No caller can construct an Opened/Admitted/recorded proof from raw fields or a fake persisted score. The target/source allocation must match that original owner, and task/current-source expiry is checked.

Each sender has a live high-water stamp: a lower authenticated stamp rejects, an equal stamp with a fresh nonce is legal (the cached ephemeral key/signature epoch uses a common stamp). Exact nonce history is scoped to the original local source/target and encapsulation, and cannot be reset by switching sender/stamp/signature, recreating a provider job, evicting a crypto cache row, or advancing the peer watermark. The packet's full authenticated sender/encapsulation/stamp/nonce context remains available through private-constructor Recorded views. No ciphertext hash or approximate Bloom false-positive policy is used.

Caller storage fixes watermark/nonce capacity. Private open-addressed tables compare exact bytes; a noncryptographic bucket function is only an index, never an authentication claim. Caller-selected nonzero peer/nonce probe budgets(default64 each) cap chosen-collision work; capacity or ProbeCapacity is an explicit unchanged-state rejection. Tables do not delete/move live entries, so their original probe-chain invariants hold. Management counts/retirement scan the bounded supplied rows. All source/stamp/duplicate/probe/capacity checks precede two infallible metadata assignments; denial returns the unchanged redacted zeroizing Opened for caller backpressure/drop. There is no live TTL/LRU eviction and no row reclamation on a newer key/stamp or ordinary packet deadline. Once nonce/peer capacity is full, that source rejects until epoch retirement; no unbounded growth or hidden disk protocol is substituted.

`Admitted` proves only crypto plus this live-ledger admission. It wraps and erases the borrowed plaintext on drop, preserves the original Task, and grants no native enqueue/write/remote ACK, durable state, or Engine admission. Message access additionally requires that the original replay owner is still live. Dropping Replay preserves public row history and latches the old Source unavailable for another replay owner; a later cache/provider or empty caller array cannot silently recreate a clean ledger for that same source.

After the surrounding native owner has actually closed/retired the original physical source, it calls the pure Source::retire signal, then Replay::retire or replay::clear_retired. Cleanup needs no clock and refuses an active source or foreign source rows before mutation. Source::retire and this pure cleanup are not themselves native-close receipts. The next source must be a new explicit allocation/intent. Public nonce/watermark metadata is retained through lost owner Drop for this reason; crypto key caches and plaintext still use their separate mandatory erasure contracts.

This is deliberately live-epoch protection. Fresh source/restart has no recovered watermark/nonces and makes no cross-restart replay claim. Actual typed load/store tokens and successful original durable receipts are still needed for any future persistent sender-watermark protection; enqueue is never commit. No unlimited per-nonce disk format/queue was invented. The containing owner supplies Engine/native/provider scheduling and physical close/persistence receipts.

Opened retains the complete caller output loan and a private used length. Message access exposes only the authenticated used span. Consuming Opened or live Admitted through recycle erases the whole loan before returning it; nonce admission and native/FC/debt ownership do not reset. Local/shared-secret and receive-cache open_recover paths return the original refusal plus a complete erased loan, allowing fixed pool reuse after malformed input, stale slots or authentication failure. A stale cache miss also erases scratch. Ordinary open wrappers map that recoverable error and erase failed output loans; callers needing the loan back use the recover API. Sealing output atomicity and wire/crypto semantics are unchanged.
