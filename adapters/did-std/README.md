# Caller-driven native DID operations

`gnunet-did-host` composes the admitted IDENTITY, NAMESTORE and existing GNS query clients. It implements `show`, `show_all`, `publish(Create|Replace)`, `remove`, `resolve` with caller-owned stable SDK Instances, explicit endpoints, one exact shared clock Arc, bounded metadata/JSON memory and an original finite Deadline. There is no DID daemon, private DID wire/RID, C FFI, key file, store backend, GNS resolver/host or hidden task/thread/Resolver.

Create `Client::new(Instances { identity, namestore, gns }, Sources { clock, identity:Some(..), namestore:Some(..), gns:Some(..) }, Limits)`. Unused ports can explicitly be None; they are never silently replaced by another service endpoint and required missing ports return Unavailable. Present sources must use the exact supplied clock Arc. Each public operation takes a grouped selector snapshot before any native admission, then uses only fixed selectors for its original phases. Sources sharing one LiveConfiguration use one coherent revision; a concurrent replacement cannot retarget an already selected ego. A later public operation can observe the replacement. Call `client.deadline(Duration)` once and use it through all phases. The Deadline retains canonical-clock high-water and original native hard time; regressions, foreign clock budgets, late polls and phase changes cannot renew it.

Every async method takes a pinned caller cancellation future and observer. SDK operations own their exact immutable frames, original request/allocation, epoch, partial cursor and outcomes. Observer events contain only provider/token/code/byte/closure metadata, never keys, full frames or document values. Completed public values are explicit owned results. Canceling a waiting SDK future does not itself claim IO cancellation: the composite explicitly cancels/drains a pending original mutation/FIFO under the original bounded grace, then closes the owner. Drop of the entire composite operation future also drops its SDK owners and physically fences their sockets. Abrupt future Drop cannot return a receipt; previously observed metadata remains the caller's only evidence. No unknown mutation is replayed.

IDENTITY lookup obtains an opaque zeroizing SecretKey from the configured service. Public-key derivation calls the existing Rust implementation explicitly and is not a network identity proof. `show_all` requires the monitor initial END before returning a bounded public snapshot; it does not claim every ego has a published DID document. Same-key alias coalescing follows the existing official IDENTITY monitor protocol, rather than adding a private name field to deletion messages.

Create accepts an existing EdDSA ego or, if explicitly allowed and no custom JSON is supplied, a missing ego can be generated through the caller's explicit Entropy port. This waits for the original IDENTITY CREATE code0 and retains only its original zeroizing material. No default RNG/file is selected by the library. A custom document requires an existing ego and its matching id; it is not used to invent a matching generated private key. Replace never auto-creates a missing ego. Actual created egos are not automatically removed if a later NAMESTORE operation fails: the original code/unknown status is preserved and the operation is not falsely described as atomic.

Publication/mutation performs NAMESTORE lookup at canonical `didd`, verifies the exact original returned private zone and label, and preserves all unrelated records/flags/expirations. Create refuses an existing managed document; replace/remove require one. Both authoritative DID_DOCUMENT and current-C TXT can be managed only after matching-ID JSON admission. Malformed/mismatched authoritative records fail closed. Removal never clears `@` or deletes the IDENTITY ego. Replace/remove retain unrelated TXT, maintenance records and other types. The final one-frame single_tx STORE is completely preflighted; success comes only from its original code0 result. Unrepresentable retained records/body are refused before that STORE, without truncation or private fragmentation. This read/modify/write is not external-writer CAS or a cross-service transaction.

Resolve submits exactly one ANY0 lookup for `didd` in the parsed public zone, with the existing GNS native client and default public API recursion128. It binds the result to the exact original query, validates/selects the official record or bound current-producer TXT with the pure library, copies only the selected bounded document and closes the original MQ. On GNS MQ loss it keeps only that same original safe readonly QueryId, which the existing client retains after retiring the old socket. The original parameters and fixed outer deadline remain; no second lookup or replacement RPC is admitted. Only a later Connected epoch and that epoch's whole write can authorize a returned answer. Partial/full exposure from older MQs is bounded history, observed with the original typed loss cause through RetainedRead, and never becomes new-source write credit. Genuine query loss/refusal, cancellation, timeout and source-port failure still terminate and physically close the owner, including an unattached connection attempt or retry. The selected GNS service owns resolution/authentication; this adapter does not decrypt records, implement a resolver, mint signature proof, or take over any stopped GNS/DHT/UDP component.

Defaults:48KiB document body policy,1024 records,256 identity rows,4096 JSON tokens, depth32 and4million JSON work units,65535-byte IPC frames/syscall slice and5s native retirement grace. All are finite and checked; JSON scratch is shared per operation and zeroizing, public metadata snapshots are independently bounded, and original frames remain in the SDK's zeroizing owners. Canonical record padding/frame constraints may refuse a large otherwise valid document, or retained unrelated data, before STORE. There is no Capacity-as-pending success stub.

Each ordinary wait registers the original native hard target before polling dependencies, independently of canonical-clock subscription stabilization. Every wake rechecks the same canonical high-water and deadline; no observation or reconnect grants a later target. Cancellation/failed mutation retirement uses its own original capped native grace and a native timer even when dependency clock/Resolver polling remains Pending. At that cap, SDK owners close without another clock sample. Actual late mutation result metadata can still be observed during the bounded grace, without reviving the failed operation.

Native close APIs report original owner retirement/known IO cause, without a separate kernel close-errno acknowledgement. Closing an MQ is not remote processing quiescence, publication, revocation/cache flush or rollback proof. First operation failures remain returned while independent cleanup causes are observed. Actual late result codes during cancellation are metadata only and cannot resume publication.

## Current official source defects addressed

Pinned `did_core.c` creates TXT16 but resolves DID_DOCUMENT65561. Rust publishes the registered DID_DOCUMENT at `didd`; bounded ANY lookup plus matching-ID TXT admission provides interoperability with the **current release producer**, not migration from a private protocol. C CLI removal clears unrelated `@`; Rust removes only the bound records at `didd`. C replace callback is empty and library remove/replace declarations lack corresponding definitions; Rust implements scoped operations through existing official NAMESTORE messages. The unused CLI1day macro is not the default: the invoked library constant is365days. These are source facts, not a claim that every C DID operation works or that C bugs are Rust protocol requirements.
