# ZONEMASTER native composition

`Owner::new` + `poll`/`drive` implement the bounded NAMESTORE monitor/full-inventory, normalization, durable expiration reservation, Rust crypto-worker, public DHT-port and private NAMECACHE pipeline. The monitor starts without its own initial inventory; only its SYNC permits an independent inventory to start. Initial record credit is one; additional monitor credit (up to five) and inventory batches (up to 1000) become effective only after the exact original NEXT frame is fully written. Each live stream retains its operation/epoch, first-input/control/initial/native/absolute targets and one opaque zeroizing pending reply. Original cursors are physically closed before loss; replacements start fresh and replay no requests. Full-inventory rounds are paced by relative-lifetime/4 windows and bounded NEXT batches, while monitor updates remain urgent. A bounded version fence prevents an old snapshot row from replacing a newer monitor event; fence pressure actually retires the old inventory before restarting it.

`material::prepare` converts relative expirations once at original reply receipt, before worker queuing. The owner selects `PublicAndLocal` from an enabled NAMECACHE and `PublicOnly` when NAMECACHE is explicitly disabled. The complete local and OMIT_PRIVATE public views retain their own minimum expirations when both are selected; the persistent authority assigns values only to selected outputs. PublicOnly performs no full local normalization/serialization, retains no unnecessary private RDATA, and signs/encrypts no unused local product. Its refresh minimum comes only from the public projection. A private-only or otherwise empty public projection returns None and still passes through the same source revision/supersession and retirement logic; no worker or publication/cache success is fabricated. Core immediately releases unreferenced no-output metadata while preserving the live inventory/monitor revision fences and old jobs awaiting retirement. CPU results are bound to an unforgeable local material-origin token, exact opaque zone authority, label, source, revision, job and original target. Sealed fields are read-only; safe callers cannot swap a different job's signed result into this job. The local token is process metadata, not a signature/proof/hash or remote receipt. Ciphertext is shared by Arc when the exact public/local products coincide. DHT accepts only `PublicPublication`; `LocalCache` has no conversion to it. `Sealed::local()` is None for PublicOnly, and the Core checks that output selection matches its configured cache mode. Empty/deletion updates supersede obsolete pending work and do not invent DHT erase.

`worker::Pool` owns finite threads and bounded input/result channels. Each original task derives its official storage query, durably reserves its expiration assignment, checks its unchanged cancellation/hard target, then seals. A late or canceled result cannot renew the target. Native owners stop before worker joins. No secret-bearing thread is detached. Kernel filesystem calls and cryptographic primitives cannot be forcibly interrupted by this owner; shutdown retains and joins their original ownership. Secrets/plaintext have zeroizing storage and redacted Debug output.

`nonce::Config` explicitly selects one absolute ledger directory and finite lifetime key bound. The foreground reads `[zonemaster-rust] NONCE_DIRECTORY`, defaulting through the ordinary configuration expansion to `${GNUNET_DATA_HOME}/gns-publication-rust-v1`, and `MAX_NONCE_KEYS` (default 65536). This is a separate private local `GnsPublication` snapshot namespace. It stores only sorted official 64-byte storage queries and their 8-byte expiration highwaters. Checked `12 + maximum_keys * 72` bounds are passed to snapshot loading before body allocation and cannot exceed 64 MiB. Entries are never garbage-collected when a label is deleted or inventory changes.

Every reservation opens the selected qualified snapshot under its exclusive writer lease, loads the current canonical image and commits the replacement through file synchronization, atomic publication, directory synchronization and readback. Same-process workers also serialize allocation without caching a body or unused counter ranges. Cooperating processes must select the same retained directory. Original writer-lock contention and the qualified backend's incomplete-initialization state retry within the same cancellation/hard bounds and retain their native cause. A fresh initializer holds its writer lease before atomically publishing the complete marker; another process cannot seize an empty canonical namespace from it. Missing history uses the record-derived minimum directly; an existing zero highwater still requires the next value. Identical complete serialized RDATA can share one common value meeting both minima; different public/local RDATA consumes the public value first and a strictly greater complete local value second. The local value also meets its own minimum. This ensures that NAMECACHE's greatest-expiration selection retains the paired full version rather than its public-only projection. A distinct pair whose public minimum is `u64::MAX` cannot allocate that later local value and returns Overflow before sealing. Equal RDATA can still share one value. PublicOnly reserves exactly one public value, including a final public `u64::MAX` when permitted by retained history; it has no unused local allocation. A previously consumed MAX still fails the next request. No record expiration is extended: authenticated record filtering still removes individually expired records. Exhausted `u64` space or history capacity refuses sealing.

The first tracked seal initializes a newly created namespace together with its first reservation. Once that local transaction is admitted, normal cancellation cannot split marker creation from the first canonical commit: the transaction finishes, then late work drops its assignment without sealing. Consumed values are never reclaimed. An existing marked namespace with a missing canonical image, corrupt format/checksum, lost inode fence or uncertain persistence refuses further sealing; there is no silent reset or legacy state migration. The original native error survives late/stale result disposal and a closed completion channel. Stop closes the bounded output without dropping queued facts, then drains them after joins; each failed sender retains at most one terminal failure in its fixed worker slot and exits immediately. `Event::NonceReserved` and the terminal report expose local transaction metadata independently of ciphertext or remote publication.

The ledger protects history from the first seal tracked in this namespace. Preserve it with the zone authority and retain the same directory for every publisher. Copying an already used zone key to another host or unrelated ledger, deleting/rolling back the entire namespace, or losing unknown prior history cannot be made safe by assuming a fresh counter. This local mechanism does not claim to prove such external history.

NAMECACHE submission uses the admitted client and complete signed ciphertext (legal wire block ceiling 65519; a maximum EDKEY GNS block is 64640). Only the original CACHE result code 1 marks that local lane successful; original raw failure/loss facts are retained separately. A saturated or failed DHT producer does not prevent local cache submission. When the checked full set contains live PRIVATE records, its RDATA differs from the public projection and NAMECACHE is enabled, the paired public DHT operation waits for the successful original CACHE reply (code 1). Queuing or writing the cache frame does not release that dependency; failure, loss or deadline retires the paired public lane within the original job bounds. Thus a routine newer publication cannot replace an installed private version with a public-only projection while its matching full cache operation is still pending. Sets without private records and identical shared RDATA retain parallel lanes. Explicitly disabling NAMECACHE preserves public operation but provides no private local-resolution guarantee. In this mode the worker actually seals only the public projection, so an unused distinct local product no longer causes a public-MAX refusal. This dependency covers the configured NAMECACHE instance. A different publisher using another cache or unknown key history can issue a newer remote block without updating this instance; a public record block carries no private records to reconstruct. Explicit cache deletion or volatile cache restart also supplies no persistence guarantee. No NAMESTORE reply or publication protocol is changed. Cancelled partial native frames remain owned until the original suffix drains or its original MQ actually closes. That cache result proves neither remote storage nor a durable cache write and authorizes no replay or withdrawal.

Every poll checks/registers all original native/child bounds before any enclosing canonical-clock wait, statistics admission or IO. Logical adjustment never remints absolute or native targets, revives retired state or renews an old lease. Real NAMESTORE/NAMECACHE `poll_native_guard` APIs settle original deadline/admission outcomes; guards are not assumed to return loss only. The cache first partial-input bound is independently retained and physically retires its MQ on expiry. Queue/capacity refusal uses registered finite backoff, not a busy loop.

`service::Server` implements the official SERVICE with no domain IPC handlers: bounded sockets, normal canonical accept/ACL/Unix credentials, bounded native option diagnostics, EMFILE suspension, original first/partial/idle bounds and tolerant-unknown handling. Accept/credential/framing failures close only the original client. A connection grants no private-key or publishing authority. `foreground::scheduled` (feature `program`) composes PROGRAM/inherited descriptors, one shared Resolver and clock, stream/cache/DHT endpoints, worker lifecycle, signals and the existing STATISTICS handle. All 16 official nonpersistent statistics names are used. A statistics setter failure retires the original owner because it can follow admission; unknown deltas are not replayed. Final destroy/report is bounded independently and occurs before Resolver disconnect. The legacy statistic "Number of public records in DHT" describes completed local inventory sets, not a remote-storage proof.

`publish::DhtFactory` supplies the production default. It owns one caller
instance brand, borrowed by one real `gnunet-dht-client-host` for this entire run;
there is no self-reference, per-record connection, extra Resolver or hidden
scheduler. Public-only prepared bytes, original query and block expiration use
official PUT type11, replication5 and DEMULTIPLEX_EVERYWHERE1. Waiting
before DHT admission retains the same original job, canonical target and
native hard; an issued PUT never becomes a fresh operation after loss.

Flights plus retained terminal events share the configured parallel bound. Logical encoded source bytes are bounded by parallel times65535, while actual
native output/attempt capacity is one frame to avoid another full parallel set
of ciphertext copies. Caller-visible submission requires the original actual
whole local MQ write; it proves no remote storage or replication. Canceled whole
writes and original Lost notices retain their own typed facts. One shared error
cause is retained with Rc for affected jobs rather than duplicated payloads.

Native hard alarms and queued terminal notices are checked before canonical
clock polling. Expiry or cancellation physically retires the shared MQ or
pending native attempt; other issued operations keep their loss notices. Only not-yet-admitted values can continue to a first PUT within their unchanged
original bounds. Clock-free `retire_io` starts no replacement IO and a missing
epoch does not imply a missing native attempt. The whole publisher's explicit
`close` also retires an idle MQ before CPU workers join. Clock-free
`take_settled` transfers its already-owned terminal facts to a pre-reserved
`Owner::StopReport`; stopping never applies them as new business success. The
foreground returns its owned per-job `Report`, and `ShutdownFailure` preserves
that same report alongside original/independent errors, including later PROGRAM
cleanup failure. The standalone main prints one aggregate local-notice summary,
not one invented error per completed write. Private cache material has no
conversion into this public port.

The standard binary installs this factory and can construct the normal
foreground composition using its configured shared endpoints/clock. Explicit
embedding factories remain supported; None still refuses rather than providing
a fake sink. SDK features `zonemaster-alloc` and `official-zonemaster` retain the
existing pure/native boundaries.
