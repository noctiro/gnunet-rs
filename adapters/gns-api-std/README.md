# Name-based GNS client API

`gnunet-gns-host::tld::Lookup` composes the existing GNS and IDENTITY native clients. The low-level `gnunet-gns-client-host` keeps its original isolated dependency graph and exposes caller-driven polling. Configuration and name selection belong to this API layer; the standard `gnunet-gns` PROGRAM is a consumer.

Selection follows the pinned public contract: a typed public-key final label first, then the longest configured `[gns] .suffix`, then the IDENTITY longest dot-boundary suffix result. Removing a complete suffix selects `@`. Invalid selected configuration is an error. Only a IDENTITY no-match result is `Outcome::NotGns`; an empty GNS answer remains `Outcome::Answer`. Service failure, cancellation and timeout retain their causes. Identity-selected single labels use NO_DHT, and multiple labels use LOCAL_MASTER; direct-key and configured routes retain the caller policy.

The caller supplies the two original Instance brands, EndpointSources sharing one clock, a configuration snapshot, request, limits and bounds. A bounded request retains one logical deadline and native hard target across identity selection and GNS lookup. `Bounds::forever()` has no native MAX timer; the original native clients retain their connection/frame/IO budgets. No resolver or task is created implicitly. `poll`/`drive`, `cancel`/`close`, typed terminal reports and consuming diagnostic projections preserve original operations, causes and cleanup ownership. Diagnostic summaries grant no reusable operation authority.

After a recoverable GNS MQ loss, the API continues driving its private raw client only when that client still owns the same original live query. The raw client has already retired the old MQ and scheduled its retry before returning this event. The API transfers the loss cause as existing nonterminal progress; its fixed-size report retains the last epoch/count. It creates no new lookup and renews neither deadline. Cancellation, lost-query, unavailable-source, clock and timeout failures retain their terminal cleanup. The standard command, DNS2GNS and proxy consumers continue the same lookup on this event; an MQ loss does not select ordinary DNS fallback.

The API performs ordinary name routing and native IPC composition. The selected GNS service resolves and authenticates records. The retained-query recovery change passes selected strict macOS/Linux API and command compilation. Prior architecture guards remain scoped to their recorded inputs; no dependency or feature graph changed here. No name lookup, key operation, native effect, model, storage or official interoperability test ran. GNS service and DNS2GNS implementations are recorded separately in the repository status; full GNUnet qualification remains incomplete.
