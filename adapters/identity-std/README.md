# Official IDENTITY SERVICE host

`gnunet-identity-host` is a caller-driven Unix/TCP accepted-MQ adapter for the active GNUnet v0.29.1 IDENTITY protocol. It requires the separately frozen `gnunet-identity` core/wire. It implements START inventory/end/subsequent updates, supplied-key CREATE, RENAME, DELETE, exact LOOKUP and longest SUFFIX lookup. This source version has no public get/set-default operation; no old default map or invented message is added.

The caller owns `Store::open`, `Server::recover(&mut same_store, actual_loaded, limits)`, `Worker::start`, `Server::new`, polling and final `shutdown`. Recovery checks the namespace/generation pair and refuses existing marked roots missing their canonical image or positive-generation empty bodies. A truly new root synchronously commits the legal empty business snapshot under the same Store lease and checks its namespace/generation1 receipt before any worker or READY. There is no await/cancellation split between fresh qualification and this commit; initialization failure retains the original storage cause. Admission uses the shared canonical accepted socket initializer, configured IP ACLs and kernel Unix UID/GID checks. RX, immutable TX, syscall quanta, snapshot references, body size and native waits have explicit limits. A complete input blocked by core capacity stays on its original MQ while old output drains. Each partially received/request-waiting frame has its original finite lifetime. A first-input bound also covers completely silent new clients. Monitor idleness after complete initialization is intentional.

`Core::begin` preallocates an immutable after-image. The one explicit worker actually accepts its owned zeroizing body before `Core::queued`. Only the private original worker completion, successful file synchronization, atomic replacement, directory synchronization, same-inode readback and namespace fence permit `Core::commit`. CREATE puts RESULT before UPDATE on the owner's FIFO; RENAME/DELETE put UPDATE before RESULT. Lookup miss is official numeric result 200; only START has an end marker. No local MQ write is a client-processing acknowledgement.

The owner and each pending output retain original typed source identities. Source loss closes its original descriptor first and erases its RX/TX/views. It does not cancel an admitted disk mutation; its eventual commit still updates other original monitors, without rebinding a recycled client slot. Dropping a drive future preserves cursors. Clock/provider failure closes every original MQ without requiring that provider. Shutdown closes MQs first, drains the original disk result and joins the sole original worker.

## Independent private store

This format is deliberately independent of C identity files. `Store::open` creates its final 0700 directory itself. Existing directories, including empty ones, must already contain its exact fixed **public** `.identity-rust-store` marker. Unmarked C/foreign directories are refused before any private inventory read. The foreground never imports `[identity] EGODIR` or `SUBSYSTEM_CFG`.

Regular files are private, effective-UID-owned, single-link, CLOEXEC and opened without following a final symlink. A held exclusive file lock and directory/marker/lock/image inode fences protect the original writer. Names never become filenames. Snapshot bodies contain plaintext secret serializations under these private permissions; no encrypted-at-rest or secure disk-erasure claim is made. Recognized private prepublication temporaries can be removed only under that writer lease; unknown entries cause refusal. Only production Store reads/checksums its own marker-qualified snapshot. Errors preserve the stage/errno and independent owned-temporary cleanup failure. Attempted publication or a lost fence is Unknown, latches the writer, closes MQs and requires explicit fresh recovery. No rollback or guessed success occurs.

Memory is bounded by the pure aggregate snapshot budget, per-source RX/TX and item bounds, one serialized pending body and at most one readback body. Snapshot clones retain an Rc and do not copy keys. Creating a new after-image explicitly copies its key owners; each and every serialized body/frame is erased on drop. Diagnostic types contain no key/frame/body/name, and the store holds descriptors/metadata rather than another long-lived secret inventory. `SNAPSHOT_BYTES` includes current, staged and historical versions, so it must allow the intended working set.

## Execution boundary and limits

`tests/native_inventory.rs` uses a published fixed non-secret mock
and describes same-MQ callback order and three durable mock mutations. Those
unexecuted assertions are not persistence or C interoperability evidence.

Filesystem syscalls such as fsync/rename can block in the OS. The finite storage wait closes network sources and stops new admissions; it cannot prove cancellation of an in-progress filesystem syscall. Explicit shutdown and emergency Worker Drop join the original worker, and may wait for OS IO. There is no detached late publisher and no invented finite-time join. `File`/socket Drop does not expose a separate close errno. Namespace fencing assumes a private cooperating same-UID namespace, not a hostile same-UID writer racing pathname syscalls. Atomic full snapshots are bounded and simple; they do not provide a WAL throughput guarantee.

## Shared raw snapshot runtime

`backend` and `worker` reexport `gnunet-snapshot-host`. Actual IDENTITY startup calls `Store::open(Namespace::Identity, directory, limits)` and validates the Loaded/Worker namespace before body interpretation or work. NAMESTORE uses its independent Namespace::Namestore directly; it never depends on this IDENTITY runtime. Existing qualified Rust IDENTITY marker/image/magic remain compatible. No C directory or private-key migration is added. The shared runtime preserves fences, generation/Job receipts, zeroization, original errno/Unknown and drain/join limitations described above.
