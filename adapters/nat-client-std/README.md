# Official NAT and NATauto native clients

`gnunet-nat-client-host` implements callable original-MQ `Registration` and single-query `AutoQuery` over existing CLIENT/Channel/Framed/RuntimeClock. It creates no default Resolver, service, helper, worker, task or storage owner. Constructors snapshot explicit endpoint selection/configuration, own bounded immutable source bytes, and open no socket until polled. A stable caller `Instance` allocates checked unique registration/query brands. Session/Epoch/WriteId/AddressId equality includes original instance pointer, allocation and serial; an old token cannot bind a reused slot or a future explicit registration. There is no wire RID.

NAT uses `Registration::new` with flags/protocol, exact native `Addresses`, a NUL-free section (one final NUL is appended), explicit `Profiles {request,response}`, immutable `Deadlines` and finite `Limits`. `from_wire` instead preserves one complete already-produced REGISTER byte-for-byte, including original section tails, sockaddr padding/length bytes and duplicate bindings. The original full snapshot stays available for this allocation and is never reconstructed from Live configuration. `from_live`/`nat_source` select actual `nat`; `AutoQuery::from_live`/`auto_source` select actual `nat-auto`, correcting the pinned C client's erroneous `nat` target. NATauto's Live convenience fixes one configuration revision before deriving both its endpoint and shared Configuration serialization. Explicit caller configuration/proposal bytes remain an explicit separate input domain.

The two native ABI profiles are mandatory constructor inputs. Use official wire `Profile::linux(Endian)`, `darwin(Endian)` or `freebsd(Endian)` for the producer/consumer. `native_profile()` is an explicit build-ABI helper, not a received-byte heuristic. The service response profile controls AF_INET6 (10/30/28), native flow/scope and fixed Unix/IP layouts; request profile also controls the active C htons16-to-native-u32 global-address length defect. `RawAddress` and raw frame APIs preserve original native bytes. No profile is silently guessed, normalized or weakened after failure.

`submit`, `submit_raw`, `stun`, `reverse`, and `add_global` queue bounded original immutable follow-ups behind the original REGISTER on the same source. Each has its own finite absolute send bound capped by the original session bound. `Queued` is native FIFO admission; `Written` is only a full local write. REGISTER, STUN, reversal and global-address messages have no ACK. Asynchronous notifications cannot be correlated as success of a submitted mutation, and none is invented. The adapter does not authenticate STUN, install a mapping, run a helper or infer connectivity.

Actual `AddressChange` callbacks keep signed add/remove and raw class bits; exactly1 adds, every other value removes. Every duplicate add receives a distinct original `AddressId`, suitable for a caller-owned app-context map. Removal uses literal native bytes (and newest matching duplicate), matching the C list semantics; class is not secretly part of the comparison. `test_address` is exact C sockaddr length/memcmp plausibility, including padding/port/scope, not canonical IP equality or reachability. A physically retired source immediately supplies no current cache/test authority.

One zeroizing `OwnedFrame` holds a received callback. `Notification` borrows that frame and original source/session/ordinal, with original allocation ID and removed add-time class when relevant. `release_notification` is only local callback consumption, with no wire credit/ACK. While a callback is held, RX applies bounded backpressure while TX and original deadlines still progress. On physical loss, `End` transfers any unreleased notification and all remaining address allocations. Consume that historical pending callback before retiring its app contexts; it cannot be retagged as a fresh source callback. Synthetic wire removals are not fabricated. Complete RX is retained across fallible callback allocation, with a finite retry timer and unchanged original deadline. A configured address quota boundary or malformed/unknown removal closes the original source explicitly instead of silently losing a callback or replaying registration.

All request/configuration/reply frames use the existing zeroizing owner; cached raw address storage also uses zeroizing fixed arrays. Debug representations redact frame/configuration/address payloads. Opaque caller app contexts stay outside this crate. A completed local follow-up write is not retained forever: its exact original Written event is its receipt. Outstanding writes remain queryable via `submission` and are returned with precise Unsent/Partial/Written state in `SourceEnd`.

Cancel/unregister physically closes the original MQ independently of clock. An unexposed follow-up can be removed from its original FIFO with `cancel_write`; canceling an initial or positively exposed write closes the whole original registration and returns every original outstanding write/cache/callback lease. No online CANCEL or remote cancellation ACK exists. Since the original MQ is closed immediately on exposed cancel/expiry, no partial suffix is drained onto a new connection. An exposed mutation without a service reply remains unacknowledged/unknown even when wholly locally written. Caller wait timeout alone does not cancel or renew anything; dropping `drive` retains original cursors and callback/result ownership. Source loss permanently ends that allocation. A new registration/query is always an explicit new constructor intent with a new brand and fresh snapshot; nothing is automatically replayed.

Registration may explicitly select `Deadlines.until=u64::MAX` for a healthy long-lived observer with no artificial overall lifetime. This is not a huge finite timeout or a periodic re-registration policy. `send_until`, any `first_input_until`, every later write deadline and its original native hard remain finite and fixed. NATauto still rejects MAX overall lifetime. All existing finite-overall behavior is retained without adding an earlier per-frame expiration.

For a long-lived Registration, `Limits.write_lifetime` (default30s) independently caps the native hard for initial REGISTER and every follow-up write. Its native anchor is captured at the original constructor/admission entry before any clock sample; it is never rebuilt by polling or progress. The remaining absolute-target duration is first minimized with this explicit finite cap, then added to that anchor. A rollback between an outer caller's target calculation and the adapter's sample therefore cannot turn that write's native budget into years, or overflow a huge Instant before the cap is applied. The original canonical send target is unchanged and may expire earlier. Callers requiring a tighter native maximum select a smaller write_lifetime. Finite-overall sources retain their existing overall/write semantics.

An optional first_input_until on that long-lived source also retains its original canonical target, with a separate native maximum of Limits.input_lifetime captured at construction. None still permits truly idle observation; it installs no artificial first-input timeout. This initial wait and each later frame's first-byte-to-release input budget are distinct.

For the long-lived Registration only, `Limits.input_lifetime` (default30s) fixes each input frame's original native hard and logical target at its first positive read, including a first read which completes the whole frame. Later bytes, polling, capacity retries and held notifications cannot renew it. The same-round native alarm is registered before returning that first progress. Copying a complete frame into the one owned notification does not clear the bound: only actual `release_notification` does. Expiration physically closes the original MQ and reports `Cause::InputDeadline` with original callback/address/write debt; it never fabricates an address-removal message or a successful write. Each genuinely released frame permits the next frame's new budget.

`Registration::poll_native_guard(cx, wait)` exposes the same native-only prefix used by ordinary poll: deferred originalEnd, nativeexpiry, then originalnativealarm registration. It performs no clock sample or socket read/write and returns only an original Ended/WriteExpired event. An idle/already-ended guard is Pending rather than repeatedClosed/WaitDeadline. Both entrypoints share one Progress/ended conversion so no source debt can be consumed twice. The TCP owner calls it before its ownclock, scan or publication turn, then fairly rotates ordinary NAT IO, interface scan and publication; even a legal tiny scan interval cannot hide original send/input hard bounds or starve useful IO.

When the long-lived observer is idle with no finite effect, no MAX Sleep/Deadline is installed. Actual native socket readiness and the original Channel clock subscription remain its wake sources. Any pending send, optional first-input wait, partial/held frame or caller observation wait registers its finite target; native guards still run before canonical-clock coherence waiting. No new instance, clock, Resolver or queue is created.

Once captured for an admitted intent, each canonical/native target remains fixed; polling, progress and clock regression never renew it. Long-lived native send/optional-first-input targets additionally use the independent finite maxima described above even when a caller-derived absolute target spans an earlier rollback. Native guards/alarms run before coherent clock/revision waiting, so revision races cannot bypass deadlines. Admission clock failure physically closes/invalidate the old source immediately, blocks new admission, and retains one bounded original End for observation. Optional first-input bound is a local policy only: NAT has no initial-SYNC/DONE and a silent registration is not evidence of no NAT/no addresses. Native reads/writes alternate fairly after REGISTER; a continuous producer cannot indefinitely starve callbacks. Allocation-capacity retry waits for an timer rather than busy-polling.

NATauto sends the exact original uncompressed GNUnet configuration serialization on one dedicated original MQ and accepts only a full result after whole local query writing. `AutoResult` transfers a single redacted zeroizing raw frame and preserves raw status, raw NAT type (including the active daemon's0) and exact serialized diff. It closes the original MQ before ResultReady. It never applies the diff, writes configuration, infers reachability, turns EOF into IPC status2, normalizes type0 to NoNat/Unknown, or fabricates successful classification. C status1 and type1 remain reported words, not independent proof of a mapping or external reachability. Cancel is original close, without retrying an old query.

Default capacities:32 pending writes,256KiB aggregate source frames (physical frames charged once),65535-byte frame,256 duplicate address rows, one callback/result frame,100ms allocation retry and65535-byte syscall slice. Long-lived Registration defaults additionally bound each write and each optional initial/per-frame input budget to30s natively; idle observation remains unbounded. One immutable initial snapshot adds at most one frame to retained source storage; constructors use bounded temporary copies, cache rows are fixed-size, and close receipts transfer already-preallocated vectors/owners. An source's native Drop exposes no independent close errno and none is claimed.

One pure allocation-brand model passed using public metadata only; it performs no native/crypto/store work and grants no IPC credit. Actual native/C interoperability and process behavior remain unqualified. This is an IPC adapter; the full NAT/NATauto provider/service composition and full GNUnet node remain incomplete.
