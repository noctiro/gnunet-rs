# Shared native process port

`process` is a source-shaped std implementation of the v0.29.1 process chain needed by ARM and later managed services. It is not a complete `gnunet_os_lib.h` or ARM daemon implementation. It calls the native operating system, with no production libgnunet backend. The original ARM public client/monitor and ARM-self launcher use this same port. The single production backend lives in gnunet-service-runtime; complete daemon reactor integration remains a separate obligation.

`NativeCommand` owns raw filename, argv, environment changes and optional child cwd, while borrowing original descriptor mappings. Filename and argv0 are independent: SIMPLE uses PREFIX as executable, expanded BINARY as argv0 and whole OPTIONS as one argument. The existing native two-pass command-string parser is `process::parse_command` (also reexported by the ARM launch layer) for GNUNET command text, including its defined quote carry/final-token quirks. The shared `_argv` port permits a genuinely empty NULL-terminated argv like the C API; the command-string caller still refuses a missing first argument. Embedded NULs are explicit native input errors. Unknown stdio bits are ignored by the same recognized1/2/4/8 tests.

`spawn(config, helper, command, limits, registry)` checks explicit finite resources and executable access before native admission. The original helper rule is preserved: absolute or ./ names use literal paths; PATH chooses the first regular existing candidate before X_OK on its original bytes. After X_OK, UID0 returns allowed, other UIDs perform stat even when no SUID check is requested. It does not add a directory rejection: a directory can pass access/stat, be admitted and then fail target exec. The failed-stat-after-successful-access timing is verified by a named, countable IO seam; nonexistent-file X_OK refusal is not relabeled as a stat-path test. Tests do not alter accounts or UIDs.

All source mappings are privately duplicated above the complete explicit target range. Advertised target numbers have separate live reservations, so no implementation relies on a same-source/target spawn dup clearing CLOEXEC. Source/target overlaps and cycles cannot clobber a later source. Parent originals and their FD flags remain owned and unchanged. Actual child target numbers form colon-separated LISTEN_FDNAMES plus LISTEN_FDS; there is no fd3/systemd-name/LISTEN_PID assumption. Explicit environment changes apply in order after generated hints. Pipe control uses the read fd in hexadecimal GNUNET_OS_CONTROL_PIPE; disabling it unsets that key. Unmapped stdio uses null; inherited originally closed/CLOEXEC stdio is sampled before temporary resources and restored by the fresh helper. The existing18 C stdio defects remain explicit differences, not Rust equivalence claims.

The dedicated helper envelope was directly refactored to carry filename separately from argv0; no old private envelope is accepted. It restores the sampled SIGPIPE class and target cwd, then calls native execvp(filename, argv). Helper admission produces an original child even if a missing target interpreter later makes exec fail and exit1. A direct target std Command error would lose that source boundary and is not used by production. STARTING does not prove successful target exec or application readiness.

`ChildRegistry` is independently owned by the caller, outliving any LocalLauncher/Host borrow. It holds each unique PID, wait authority and optional control writer. `OriginalChild` and `ControlWriterToken` are lookup capabilities only, with Arc allocation identity checked using ptr_eq/manual pointer hashing and checked monotonic generations. Cloning a token never duplicates OS ownership. Completed events retain one capacity credit until taken. ECHILD immediately retires the original record/control writer and returns the ownership-loss error, without inventing an exit or retrying a reused numeric PID. External concurrent waits violate the registry contract. Generation exhaustion refuses new admission; signal, writer close and consuming waits never need a new generation. The client defers only for recoverable active/completed credit; permanent generation exhaustion surfaces as a resource error when attempted.

`signal` and `signal_control` first validate the original live record, then perform the source policy: an exact one-byte control write succeeds; any error or short write falls back to native kill of the same unreaped original PID. Failure does not close or replace the control writer. `signal_report` additionally retains the write class/errno; it changes no route. Actual tests fill a nonblocking pipe to EAGAIN, successfully call kill(0), make the still-live child drain it, then successfully write through the same token again. Real EPIPE and one-byte delivery are separately observed. EINTR and zero returns are finite test seams followed by native kill/wait, explicitly not claims of a interrupted one-byte syscall. Source-extracted complete C kill body/struct with the same finite write seam is compared separately from unchanged-library probes.

The port never changes the parent's SIGPIPE handler or mask. With default unblocked SIGPIPE and a closed reader, native write may terminate the calling process before any fallback. Actual new-exec C and Rust callers both die by13 in that profile; no successful EPIPE return, kill fallback or consuming parent wait is fabricated. Normal Rust callers generally use the inherited ignored profile. A successful pipe write or kill attempt still does not prove application processing or death.

ARM-self is different from a managed child: arm_api.c destroys its process wrapper after starting. LocalLauncher therefore closes its newly created control writer immediately after admission, while the independent registry still owns original PID/wait authority. Managed callers retain the writer. Dropping/canceling a host borrow never kills or loses the registry's children; the final registry, like std Child, must be retained and explicitly drained. Its final Drop does not forge waits, kill a daemon or block indefinitely.

ARM public client/monitor behavior and resource ownership docs remain in ../arm-std/README.md and API.md. The SDK exposes this shared runtime through optional official-service. This component does not implement the whole ARM daemon reactor, startup/privilege/CLI/testing-wrapper chain, parent-control receive dispatcher, arbitrary OS utility APIs or a Windows host. Shared runtime readiness is directly reexported; no private second native registration implementation remains. All native unsafe operations stay in the single existing audited native_spawn/helper boundary, with the raw integer kill call added there; protocol/core code retains its prohibition. Linux-specific execution still needs a Linux host profile; present normal-library/Unix/TCP observations are on macOS.
