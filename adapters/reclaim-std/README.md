# RECLAIM native SERVICE

`gnunet-reclaim-host` implements the active GNUnet v0.29.1 RECLAIM application IPC over accepted SERVICE connections. It drives the existing `gnunet-reclaim::business` state machine through production NAMESTORE and GNS clients, explicit OS entropy, Rust identity public-key derivation and the pinned credential helper. It creates no GNS resolver, persistent store, background task, worker or per-request Resolver.

`Server::new(&namestore_instance, &mut gns_instance, core_limits, native_limits, ports, system_providers)` constructs bounded metadata. `Ports` carries the original SERVICE ACL/Unix credential rule, one shared `RuntimeClock` Arc and NAMESTORE/GNS `EndpointSource`s using that same Arc. The caller must drive the shared Resolver and `Server::poll(cx, listeners, until, observer)` fairly. `drive` is its cancellation-safe wait wrapper. `admit` permits independently accepted canonical connections. `request_shutdown`, `close_client` and `close_all` explicitly retire original owners; `Drop` closes them as a final fence.

## Real provider path

There is one shared NAMESTORE general MQ, one shared GNS query MQ and at most one dedicated NAMESTORE iterator MQ. Providers are bound only after the SDK `Connected` event. Every application request owns a private slot/allocation token and official RID. Every accepted provider operation retains its original business Effect, SDK operation/query, original epoch, immutable encoded length, positive-write count and fixed deadline. Actual local whole-write receipts permit an original remote result; they are not STORE success, GNS authentication or client delivery. NAMESTORE replies retain their raw result code. GNS answers are structurally decoded by the existing client; the configured GNS service owns resolution and record authentication.

The OS provider opens `/dev/urandom` explicitly, after foreground UID/GID setup. It only derives a public zone key from an opaque private key accepted over the ACL-protected application MQ. No key file, identity file or C private material is read by this service. Key-bearing input, copies, provider frames, serialized presentations and outputs use existing zeroizing owners. Diagnostics contain original token/RID/status/cause metadata, never keys, records or ticket capability names.

Active operations include attribute/credential store and delete, ticket issue/consume/revoke, and NEXT/STOP-controlled attribute/credential/ticket iteration. Iterator snapshots come from the NAMESTORE iterator and require its END. A failed scan does not manufacture END. Each returned row is checked against the exact original private zone key, including its key type. GNS ticket and referenced-record lookup uses the existing query client. The ordinary API recursion default is128, matching pinned `gns_api.c`; policy bits/depth are explicit settings.

The JWT presentation helper returns the complete original credential payload, with its original credential ID/type. This is the active C behavior: requested attributes do not prune JWT bytes, and the helper does not verify issuer, signature or expiry authenticity. Unsupported/inactive presentation providers fail explicitly. The native adapter does not upgrade a parse-only result to verified authentication.

## Bounded ownership and cancellation

Default native limits are16 accepted MQs,32 original jobs,8 jobs per MQ and one retained TX frame per MQ, with complete official frames bounded at65535 bytes. RX storage is acquired by accepted connections. Business payload/tables have the separate default16MiB shared quota,256 scanned rows,256 records per set and256 items. The general provider slots are1 each; scanned data occupies the original business quota rather than an unbounded native duplicate. Actual RX/TX framing, metadata, transient serialization buffers and allocator overhead are outside that business quota but remain independently bounded by native limits. No per-job thread, per-peer Resolver or unbounded diagnostic queue exists.

One mutation-job lane spans the original scan/plan/write sequence to avoid collisions between this service's own mutators. It is released once the business result is ready and provider debt is gone, before a slow application must finish reading. Read-only jobs can proceed concurrently. This is conservative global serialization, not a private wire transaction: other external NAMESTORE writers can still race a scan and multi-label ticket revocation is not globally atomic.

All native/logical deadlines are fixed from the original request. A canceled/expired mutation is not replayed. Its admitted NAMESTORE operation is canceled once and its original partial suffix is drained, or its original MQ is physically retired at the original bounded grace. An exposed STORE without a definitive original reply is Unknown, not unsaved or successful. Late success can update only that old job's committed count; it cannot revive a request, response or replacement generation.

Consume authorization/reference GNS reads can retain their exact original query across MQ loss. The native client first retires that MQ and schedules retry; this adapter parks only the corresponding read effect before revoking its old Source. The effect and occupied native query slot prevent a second lookup. Only an later Connected event can bind the same effect/query to a distinct live Source from the same factory. Request identity, start time, canonical deadline and native hard target stay unchanged. Old callbacks remain fenced, and a result requires the new connection's write and reply correlation. Earlier positive/whole-write facts remain bounded history and never grant new-source write credit. Cancellation, genuine query loss, timeout and physical cleanup keep their terminal paths; NAMESTORE writes do not enter this recovery path.

Dropping a pending `drive` future does not cancel an MQ, cursor or job. Actual application loss closes its Framed owner, cancels its business jobs and preserves provider debt. STOP targets only the original same-source RID/kind; it is never a new operation. Resource refusal closes that original app MQ, allowing other MQs to continue rather than retaining a capacity-blocked frame ahead of STOP/NEXT forever. Slow responses have a finite original output age. The six work classes and per-source/job rotation bound each poll turn.

`close_all` does not sample a clock. It closes each application MQ and all three provider-owner classes before retiring original pure effects, even if the clock or Resolver already failed. Reports preserve output exposure, known committed STORE codes and Unknown outcomes. The shared CLIENT SDK exposes owner retirement and known IO causes but no independent kernel close-errno acknowledgement; no missing close-error field is represented as remote withdrawal, GNS cache flush or external processing quiescence.

## Execution

This qualifies the executed STRING/ticket profile. Authentication of credentials and the JWT/presentation, revocation, cancellation and recovery profiles require independent qualification. Publication, cache propagation and revocation freshness remain the corresponding services' responsibilities. Ticket refresh controls record refresh/expiry when writing; it does not start a hidden periodic republisher.
