# Native ABD service owner

`gnunet-abd-host` connects the official ABD IPC decoder, the single bounded `gnunet-abd` proof engine, native GNS queries, and private NAMESTORE credential collection. The caller binds standard SERVICE listeners and explicitly polls `Server`; the adapter starts no task, worker, Resolver, secondary service or private protocol.

Each accepted MQ owns a bounded set of distinct original RIDs. A query holds its global reservation through proof work, source retirement and its final whole write. It has an explicitly polled local future, a generative pure-query instance, one GNS owner with at most64 original pending lookups and, for collection, one private NAMESTORE lookup. Separate RIDs may make progress while one result waits for output. Shared CLIENT endpoint selectors are frozen together, share the caller's exact clock and Resolver capability, and never silently retarget during this query. Selection does not prove daemon identity across different MQs.

Collect derives the public subject from the supplied secret, queries that original zone's `@` label through NAMESTORE, checks the returned zone/label/status, and accepts only PRIVATE DELEGATE records. The private frame/key owners erase on release. Verify authenticates the canonical signed credential bytes. GNS ATTR/DEL callbacks must match the original epoch/query, must follow the whole query write, and retain their original source token through completion or physical source close. Signed DEL verification, expiry, normalization, conjunction and linked-role proof rules use the shared pure implementation. Invalid independent records can be ignored; IO, clock, resource, non-success private lookup and cancellation failures cannot turn into an absent-record or authorization result.

The server emits real995 intermediate chain frames for verification and actual992 terminal frames for either request kind, matching the pinned C service/API. Queue admission is distinct from partial and whole local writes. A terminal frame is eligible only after all query sources retire, and authorization validity is checked again before output. Backend/clock/resource failure closes the original client MQ; it is not sent as a false `found=0`. Collection suppresses intermediate frames as the C service does. The pinned C plural credential format cannot preserve a subject-role leaf; such an output returns `Unsupported` rather than dropping that restriction or adding a private format. Canonical GNS DEL records retain the full restriction.

Client EOF, deadline and explicit shutdown first physically retire that client's MQ, then cancel and close every original GNS/NAMESTORE owner without sampling a clock. No query is automatically replayed after source loss. Actual first failures and independent cleanup causes remain in `ClientReport`; whole terminal/intermediate writes and retired-unwritten/retired-partial frames are separate observations. Any unretired debt fails the service shutdown gate. Soft shutdown stops admission and retains the existing finite work/output bounds; the foreground owns its independent grace deadline and may request Immediate retirement.

The default deployment profile is32 IPC clients,32 global queries and8 RIDs per client, with an8MiB reservation per query and256MiB aggregate native/query reservation. First input is30s, a partial frame15s, an original operation120s and each queued output at most15s, capped by that same operation. The first-input target is captured at `Server::admit` entry before diagnostics, credential providers or allocation. A complete original frame retains its operation target even while global quota prevents admission. Targets are not extended by partial IO, reconnect, output pressure or repeated observation. The selected GNUnet absolute clock supplies explicit UTC uncertainty; independent native hard bounds also apply.

Aggregate admission charges selected fixed endpoint storage, owner/row/order backing capacities, client RX capacity, TX node capacity and the allocated Sleep payloads. A queued frame payload stays under its original query reservation instead of being double charged to the client. Each query must fit the configured pure-core quota plus its future size and a conservative native envelope of eight maximum-sized frame buffers and256KiB metadata. Runtime allocations are fallible and native frames/names are bounded; this is an explicit service admission reservation, not measured RSS, allocator overhead/temporary allocation peak, OS socket storage or an arbitrary caller clock/Resolver implementation's total heap. Configuration maxima need not all be simultaneously reachable under the aggregate reservation. The original source/normal program owns its separate process resources.

`ready()` means initialized IPC admission only; normal READY requires the caller's listeners. It proves no backend connection or authorization. ATTR's C u64 alignment remains explicit in the core profile. Ordinary CLI, SERVICE program/configuration/lifecycle and record text are separate production callers, not implemented again in this adapter.
