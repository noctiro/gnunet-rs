# Native TOPOLOGY runtime

`Runtime::new` takes external stable CORE/PILS/general-PEERSTORE/monitor-PEERSTORE instances, explicit CORE/PILS/PEERSTORE/TRANSPORT `EndpointSource`s, and finite limits. It snapshots all selectors together (one revision per shared LiveConfiguration) and requires the same RuntimeClock. It creates no socket until polled, no hidden Resolver/task/thread, and no private file/key/store owner. Pure `Engine` stays outside native protocol details. `poll`/`drive` cancellation preserves original cursors and effects; `close` stops every MQ independently of clock, preserves cleanup failure separately, consumes original close completions, and drops no source into an implicit replacement.

Existing native CORE, PILS and PEERSTORE clients are reused. The small private TRANSPORT owner reuses the existing official `application::Preference` encoder for exact44-byte1300/1301 frames over shared CLIENT/Framed. It retains immutable cancellation/new-suggestion frames and the original pure effect until both whole writes complete. No ACK exists. Partial failure/close reports original byte exposure and source epoch; original hints disappear only after the original MQ physically closes. Fresh policy can create a new effect on an actually new source. No private service-info field is added to CORE INIT; pinned CORE's prefix is8 bytes plus BE16 message types. Gossip subscribes to full type16 HELLO_URI and uses best-effort priority1.

The PILS observation supplies own identity and its exact coverage. Identity change fences the old CORE source before using new local identity; mismatched CORE/PILS identities do not retag old peer connections. CORE initialized self notifications are excluded from remote rows. Incoming complete HELLOs are verified with the shared HELLO code and kept under a bounded FIFO with original ingress epoch/sender and original deadline. Capacity drops are explicit and produce no invented remote/store acknowledgement. No expired HELLO is advertised.

PEERSTORE monitoring uses a dedicated MQ, exact subsystem `peerstore` and key `peerstore-peer-hello-uri`, initial iteration and credit/SYNC. Cache removal removes local HELLO bytes. Every retained HELLO is signature checked, with metadata-only address limitations preserved. Monitor source loss clears current synchronization; a fresh original monitor epoch must reach SYNC. It does not assert uninterrupted notification continuity.

Incoming gossip invokes the public hello_add algorithm through the general native PEERSTORE owner: iterate that exact peer/key; keep a valid newer-expiration record; otherwise wait for iteration END before submitting an exact REPLACE STORE with the original full message and HELLO expiration. Each scan/STORE/NEXT/STOP is an original operation/epoch. Only STORE_RESULT produces `HelloAddStatus::Store(raw)` (GNUNET_OK is1); queue/write/scan end and skipping an existing newer record are separate outcomes. Loss of an exposed STORE is unknown and never replayed. Cancellation/finite bounds retain the original partial suffix/STOP only through the first cancellation anchored at min(native hard, current native time)+grace, then physically retire the original MQ. No store files are opened by this adapter.

All native sources have explicit periodic finite rotation and the daemon intent has one original finite lifetime (defaults: sources1h, daemon365days). Reconnection creates fresh physical epochs and explicit fresh monitor synchronization/current-policy intents; it never renews an old mutation deadline. Native guards and timers run before coherent clock waits, including revision races. Clock failure closes every original source before returning. Core cancellation and PEERSTORE drain guards are independent of clock progress. Native error/capacity causes remain typed. Temporary retained-record allocation failures back off to the runtime's finite tick rather than spinning on Capacity/WouldBlock.

Default bounds:63 known remote rows,1MiB cached raw HELLO bytes,64000-byte HELLO frames,256 addresses,8 pending incoming HELLOs, one hello_add scan/STORE, one TRANSPORT control change, at most63 CORE sends, fixed finite parser scratch and suppression matrix. Shared CLIENT queues and source byte accounting have separate finite budgets. Reaching a configured peer/byte capacity is an explicit resource boundary, not an excuse to overwrite original live debt. The runtime does no hashing for cache deduplication, no probabilistic Bloom lookup, no on-disk state, no address authentication, and no network-delivery inference.

Two pure public-metadata policy models passed in the core; they confer no native/provider credit. Mixed C/Rust interoperability and a running topology process remain unqualified. Statistics are structured diagnostic events rather than statistics-daemon export. Legacy C scheduling/Bloom false positives and allocator hooks are implementation internals and are not reproduced.
