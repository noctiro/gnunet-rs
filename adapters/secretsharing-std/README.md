# Original SECRETSHARING780/781 SERVICE

This caller-polled service connects the standard781 IPC request to the
installed `gnunet-secretsharing-decrypt-host`. That owner performs the original
PILS identity/exact signing, sealed partial verification and threshold Combine. Threshold-one781 uses a genuine verified local partial and no Consensus MQ;
higher thresholds retain the contribution/conclude/525 workflow. This
service does not reimplement any signature, group arithmetic, sampling, proof, Consensus or
private RPC algorithm.

Only an original `Decrypt::Done(Plaintext)` can form standard782 with raw
BE32 success1 and the original128-byte plaintext. Mathematical completion,
response formation, positive partial local writes and a complete136-byte local
write are separate facts. A full local write is not proof that the original
client callback ran. Error, EOF, cancellation, source loss, expired targets,
resource refusal and insufficient quorum never become a successful782. For threshold one the same full roster/cipher/share checks and sealed verifier
are used, and Combine must still match the public-key interpolation. A larger
roster with threshold one is not converted into a singleton share. The original
start gates its result, all original targets stay fixed, and the PILS
source is physically closed before Done and checked idle by this service
before output. No insert, Conclude or525 is fabricated;
`local_threshold_one` in DecryptFacts only records path selection, separately
from genuine verified/completed facts.

Standard780 routes after observing the current PILS identity. Threshold1
with an empty input roster or exactly that local peer uses the existing singleton
path. Other valid requests move the same idle client into the original two-round
generation owner. Duplicate peers and invalid thresholds retain admission
errors; they do not silently use the singleton path. Generally usable FAIR is
still obstructed by the fixed response width. A failed attempt returns
its original error, without a placeholder share, fake783 or private error format.

The singleton owner observes and retains the verified PILS identity/epoch. It uses the existing bounded PolynomialGenerator to sample fixed C's full
nonzero scalar range1..q-1, without a small-exponent restriction. The same owned
CommitmentJob computes g^a0; original-index0 Horner evaluates that same constant
polynomial. The shared pure AggregateJob then verifies that scalar against the
original coefficient commitment, adds the local contribution and derives
the output key/roster/sigma through the same original-index aggregation used for
multi-dealer mathematics. Public key and sigma0 are the commitment, secret
share is a0, threshold/count are1, my_peer/original_index are0 and peer is PILS. The private output helper requires the original local row at position0 and
explicitly refuses a larger aggregate roster; pure
multi-dealer algebra cannot grant this service multi-party DKG authority. Its mathematical state owns exactly one generator, owned commitment job,
polynomial/commitment pair, aggregate job or completed material. Bounded turns
advance that owner in place; only completed transitions transfer the original
allocations. There are no parallel optional job slots or separate phase tag. Allocation accounting follows the current owner once, including spare vector
capacity; inline storage reserves the largest stage rather than all mutually
exclusive jobs together. Identity, original targets, start waiting and source
retirement remain the outer owner's responsibility. A refused consuming
transition does not mark the external PILS source closed. No Paillier encryption, remote FAIR certificate or Consensus receipt is needed
for this one party's known local contribution. Nothing here qualifies a remote
contribution or solves multi-peer generation. Legacy direct C peer identity and
selected current PILS identity are not silently equated.

Random preparation may precede original start, but actual783 formation waits
until that absolute start. Original deadline only shortens finite admission;
start at/after that finite bound fails. No phase, permit wait or future drop
renews it. Each entropy boundary checks the original native hard; provider
failure clears partial output and retains the first cause. PILS is
observed before each bounded arithmetic turn; identity/epoch loss or expiry
fails the original operation. The source is physically closed and idle
checked before exposing complete430-byte783 to the secure output queue. Temporary scalar exports, share bytes, response storage and queued frames are
zeroizing. Cancellation physically closes IPC first, then PILS and secret jobs.

The fixed C service permits one decrypt session per original client; its public
API creates a new MQ for each781 and closes it after the actual782 callback. This service likewise adopts one780 or781 per original MQ. Any subsequent positive
request bytes retire that original owner. EOF is a source/cancellation event,
not an HTTP-style input terminator or a decryption result. No attached source
replay or automatic restart of an uncertain contribution/signing operation is
introduced.

`Sources::new` coherently snapshots the selected PILS/CONSENSUS endpoints with
the same clock Arc, then holds fixed endpoint selections. Per-session
clones share the selected endpoints rather than duplicating a full config. Sources are caller supplied; no hidden Resolver, worker, service or runtime is
started. Each admitted client future owns its stack PILS Instance and actual
Decrypt owner under the Server's fair polling, without manual self-reference.

Admission captures finite canonical/native whole and first-input targets before
credentials/diagnostics/allocation. A positive first byte captures an immutable
partial-input target. At completion that same target is checked before
clearing. Original780/781's absolute deadline only shortens the initial whole
bound; job construction, quota waiting, retries, source phases and output do not
renew it. FOREVER/far-future raw deadlines remain capped by the original finite
service bound. Each response queue/write has its first fixed output target,
further capped by that original bound. Actual written prefixes are retained
before a subsequent clock error/late classification.

A bounded exact Zeroizing copy transfers the complete original private frame
from Framed into Request. `release_frame` immediately erases Framed's used
input. The framing allocation and request allocation coexist briefly and are
charged separately. A queued Request remains private/zeroizing and can observe
client EOF/extra bytes while waiting for an operation permit; it does
not create crypto/native work merely to wait for capacity.

Default resources are16 original clients,8 operations,65535-byte frames,
32 MiB conservative reservation per native owner and512 MiB total service
reservation. Actual boxed future/report metadata, bounded client input/output
allowances and the original operation reservation are accounted separately. Two report boxes are allocated before original IO so the terminal Event can
move an existing box without a new completion-time allocation. The per-client
framing allowance also covers its one private queued Request. The native owners
additionally validate their own roster/payload capacities. The singleton
owner uses the same operation reservation and existing math/PILS limits, checks
coefficient/commitment capacities, and creates no Consensus MQ. Counts and
byte bounds are independent, so not every maximum payload is promised to fit
simultaneously. These are retained admission budgets, not an allocator/RSS,
constant-time, throughput or peak-transient-memory claim. Caller-retained
terminal reports belong to their new caller owner.

`IndexOrder` is explicit: the original C share's uint16 indices were copied in
native byte order. The default is the selected Rust target's native order;
there is no try-both heuristic or new wire tag. The original share bytes, peer
order, local index, threshold, ciphertext, start/deadline and signature scope
remain owned by the decrypt pipeline.

Cancellation first physically retires original IPC, then independently closes
PILS/CONSENSUS and erases mathematical work. This path needs no healthy
business clock or Resolver. Report preserves source causes, signature
operation/completion/refusal/unknown status, signer/epoch, original contribution
receipt, real525, distinct verified/rejected counts and idle/debt facts. Scoped PILS brands become numeric diagnostics only when their original owner
ends; those numbers cannot authorize another operation. Private share bytes,
owned plaintext and unexpected private crypto result bytes are never Debug
formatted. Unknown old work is not reissued.

Server shutdown stops admission, signals every original local control and polls
every original future's clock-free retirement path. A failure in one client
does not skip other clients. Nonzero original debt prevents successful service
shutdown; dropping Server is not used as a successful shutdown receipt. Normal
SERVICE startup, access policy, signals, Resolver and ready/stop diagnostics are
provided by `apps/gnunet-service-secretsharing`.

Source architecture and selected
checks do not establish whole-GNUnet or full C-to-Rust generation acceptance.

The normal780 entry adopts general requests into the two-round
`Generation` owner after observing the original PILS identity. Exact-local and
empty threshold1 requests retain the existing singleton fast path. Multi-party
requests move that same client into keygen; they create no replacement signer
epoch. Exact source/signature/whole-write diagnostics and unknown outcomes are
retained. A FAIR TooLarge or other provider/resource failure remains an
error; it is not reported as successful empty output. Standard783 output uses a
zeroizing Vec with retained capacity and the secure queue-copy peak
charged until whole output or original physical retirement. Full general FAIR
and unchanged-C multi-party generation qualification remain open.
