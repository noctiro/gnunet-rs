# Public HELLO-add helper

`hello::HelloAdd::start` exclusively borrows an idle general `Client` and caller address scratch. `Client::is_idle()` additionally checks undelivered original observations so the helper cannot swallow an earlier operation's completion. The getter is read-only and grants no result/source authority. An existing active connection may be reused. No hidden client, MQ, Resolver, worker or private wire is created.

Incoming HELLO parsing/signature/expiry and full STORE width are checked before scan admission. Copies are fallible and retain only frame bytes; the operation is bounded by both caller deadline and HELLO expiration. Signature coverage is explicit; normal profile does not authenticate addresses. The helper drives an exact peer/subsystem/key scan on the original MQ, validates cached metadata before treating it as newer, grants one credit at a time, stops when newer data is seen, or submits REPLACE only after the original successful END and same original physical epoch. Invalid/resource-refused cached data causes explicit failure with no store, rather than authorizing replacement of an unknown possibly newer record. This safely avoids the C callback's unchecked cached-expiry dereference.

`AddProgress::Native` preserves original connection/record/write/result/loss events. `Completion` correlates original scan, optional store, peer, coverage, epoch and raw outcome. StoreResult is the raw STORE_RESULT; ExistingNewer is a checked cache observation plus original STOP/local source-retirement outcome, not a new durable write acknowledgement. Unknown writes, partial prefixes, canceled/expired work and local STOP writing never become saved success. There is no automatic re-scan or STORE replay after source loss. The same original Client owns queued suffix/completion debt until whole writing or physical source retirement.

Caller waits are cancelable without changing operation state. Explicit cancel preserves the original fixed drain target; a late poll cannot renew it. Native hard checks precede Client logical clock waiting. `close`/error/drop physically close the original MQ if active; an exclusive idle-start borrow ensures this cannot cancel another caller's job. Normal completed helpers drop without closing the still-reusable Client. `take_completion` observes the same once-only terminal fact without clock/IO and is useful before handling an unrelated late signal. Complete caller cleanup still owns its original Client and Resolver.

This helper uses existing HELLO verification and concrete PEERSTORE Client effects, not a trait success stub or new storage implementation. It adds no C dependency, key file, local private key, transport runtime or private request ID.
