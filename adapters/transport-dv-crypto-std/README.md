# Actual PILS DV provider glue

Host-only composition, separate from the default noalloc material crate. `SealJob::begin` calls the existing caller-owned PILS Client::sign with the exact purpose30 region; `OpenJob::begin` calls Client::decapsulate with the original enc32. New provider admissions use the latest verified `KeyTarget::Exact` announcement only after matching the original MQ epoch, peer, address hash and signature coverage, and checking both announcement expirations. Same-key/same-context HELLO revision or expiry refresh does not replace the original material/derivation identity. Each job retains the caller's original identity, Task, expiry and source; queued operations and existing jobs are never retargeted or replayed. A different key/epoch/address context or coverage still fails rather than silently changing the original authority.

`operation()` and `token()` retain both original provider and surrounding DV identities. Complete borrows the Completion, so rejecting another job's result never consumes/erases that unrelated response. It requires exact operation, signer/recipient public and original MQ epoch (plus unexpired original/identity); the core performs the EdDSA/AEAD checks before producing the redacted output lease. Raw KEM secret is only borrowed from the zeroizing PILS Secret32 result. No copied key, provider success, source identity, clock, MQ, queue, native write, ACK, or external callback is fabricated. Scratch wipes even on early wrong-operation/refusal paths.

This glue does not drive or own Client. Caller drives the original existing PILS owner, binds token→original immutable DV operation/message/route, and checks the same immutable logical/native targets before/after CPU work. On provider/source loss it retires the original pure Source and cancels/closes the original native debt. `cancel(self,client)` invokes only the original typed local PILS cancellation; there is no private wire CANCEL, no automatic replay, and physical FIFO debt remains inside that original Client until completion/loss/close. Dropping a job erases local KEM material but does not pretend to cancel that native debt. No unbounded task, timer, pool or fallback provider is added.

Replay, persistence and Engine admission are separate owners. This provider glue does not issue their grants or complete their IO debts.

## reusable-epoch provider jobs

`cache::SealJob::certify` consumes the matching signature completion into reusable SendMaterial after original operation/signer/MQ/identity/expiry checks. `cache::ReceiveJob` actually admits one original enc32/Task into the existing PILS client, accepts only the matching source/identity/operation Secret32 and copies those32 bytes once into the zeroizing recipient material. Signature proof starts empty. ReceiveJob cancellation remains original typed local PILS cancellation with native FIFO debt retained in Client.

PILS-backed material task expiry cannot exceed the original identity observation's expiration; refusal never silently extends/clips the task or rebinds it to a newer source. Material Task expiry describes its fixed epoch lease. It does not supply the original packet's provider-operation budget.

Both cached producers require `cache::OperationBounds`, copied from that packet's original canonical and native targets before PILS admission. `cache::SealJob` owns the existing one-shot signing job plus those bounds; `cache::ReceiveJob` retains them alongside the KEM request. Admission checks the original operation before minting a PILS operation. Completion checks those same operation targets before and after material construction, independently of the material lease. An expired completion drops its zeroizing material and cannot be installed by the returned API. No cache hit renews either original bound. The top-level one-shot `SealJob`/`OpenJob` APIs keep their separate packet Task and completion behavior.

PILS request APIs have no per-request wire deadline. The surrounding Runtime must retain its original packet row, arm/check both clock bounds, reject late material installation and cancel the exact admitted operation on expiry. A constructor that already admitted a request retains and returns its job; it does not lose copied FIFO debt through a post-admission bare error. Cancellation remains available after expiry and still affects only the original typed operation; it does not claim physical queue drain. Caller reserves fixed cache slots, maps provider Tasks/OperationIds separately from each packet Task, and drives/closes original Client debt. Host code introduces no new provider/clock/endpoint/global, queue, timer or storage path.

`learn` supplies PILS purpose37 initiation with fresh caller entropy and purpose36 forwarding over an original verified frame. Original tasks, operations, identities, successors and native receive instants remain bound across provider waits. Completion independently verifies the signature before exposing canonical bytes; forwarding delay uses native elapsed residence. Signed frames do not count as sent probes, replay/store admission or validated routes.
