# Actual HOSTLIST native composition

This implements the active pinned GNUnet v0.29.1 HOSTLIST roles over Rust-owned HTTP/TLS sockets, native CORE/PEERSTORE/STATISTICS clients, and one explicit qualified snapshot worker. Public production provenance is in the handoff's `public-source-inputs.json`; pin `346358e26d4dcc2dc4f51bef5d52dca29c7d8165`. There is no production libgnunet FFI and no C daemon/helper wrapper.

## Callable ownership

Construct `gnunet_hostlist::Core`, stable outer `Instances` (CORE and separate general/monitor PEERSTORE domains), fixed `Sources`, one existing shared `ResolutionContext`, immutable `Options` and `Limits`. `Runtime::new` snapshots related live native selectors together and verifies their clock identity. HTTP/proxy inputs are independently explicit caller-owned immutable values; the production foreground derives them from the same unmodified prepared configuration. The supplied domains outlive all original typed callbacks. `Runtime::poll`/`drive` advance owned cursors; dropping a borrowed wait preserves them. There are no hidden HTTP pool, connection tasks, default resolver or implicit worker startups.

`Options.listeners` are already-bound public TCP listeners. `Options.advertised` is a configured external claim, with no reachability proof. `readiness` reports CORE INIT_REPLY, general PEERSTORE attachment, monitor SYNC where required, and listener count. It does not assert bootstrap produced a connection. `request_stop` stops new work/accepts and retains original bounded debts; `close` stops all physical network owners before metadata retirement, independently of fresh clocks. `shutdown_durable` then consumes original worker results, final history commit and join. Filesystem syscalls may block; a socket deadline is never called a canceled fsync. Independent cleanup failures remain separate from the original error.

## HTTP and TLS bootstrap

`http::DownloadJob::new(fetch, resolution, tls, proxy, limits, original_hard)` reserves an original owner. No socket opens until driven. Its logical deadline and immutable supplied native hard bound cover DNS, proxy, TLS, HTTP, redirects and handoff into PEERSTORE. Pending-future drop retains the same task/cursors. Cancellation drops that exact owned DNS/socket/TLS/HTTP future; there is no retry after a partially exposed request or source loss. Local native bytes include TLS/proxy overhead and never establish remote application processing.

Hyper1.12.0 parses/serializes HTTP/1.0/1.1. Connection futures are polled inside the owner, with bounded header count/buffer, request/response native wire bytes, decoded body, frame work and address probes. Bodies are incrementally consumed with foreground yields; no unbounded collect is used. Standard chunked/content-length/EOF framing comes from Hyper. There are at most four redirects by default. Initial HTTPS URLs stay HTTPS; initial HTTP URLs may redirect to HTTP or HTTPS, matching the active libcurl settings. Redirects preserve the original job/deadlines, never become a retry of an errored socket. Origin Basic credentials are scoped to the original URL origin or an explicit current URL userinfo, and are never forwarded as proxy authentication.

Rustls0.23.46/tokio-rustls0.26.6 use the explicit owned AWS-LC provider, non-FIPS native/asm primitives, and public webpki-roots1.0.11. There is no global provider install, client key, key log, insecure hostname/certificate override or plaintext fallback. X509 validity uses the standard Unix wall/SystemTime provider, matching libcurl. This trust clock is separate from the shared GNUnet RuntimeClock used for operation deadlines. Session resumption/early data are disabled. The code does not claim pure Rust cryptographic primitives or FIPS qualification.

All ordinary target/proxy hostname resolution uses the original shared GNUnet Resolver context; `TcpStream::connect` receives already selected numeric SocketAddr. The original address callback is returned only after its socket/proxy-target effect actually starts; its query drain remains attached to the original connection. No target callback is held while opening a different proxy DNS/socket attempt. IPv6 URL brackets are removed for numeric resolution and TLS server-name checking, while HTTP authorities remain bracketed. Socket initialization reuses the native reactor boundary; original warnings and fatal errors are preserved by probe id.

configured proxy modes are HTTP, HTTP_1_0, SOCKS4, SOCKS5, SOCKS4A and SOCKS5_HOSTNAME, including bounded username/password negotiation and HTTP CONNECT for HTTPS. HTTP proxies support an explicitly HTTPS proxy endpoint as well. SOCKS4 uses the added AF_INET-only shared lookup port; unsupported custom contexts explicitly refuse it. SOCKS5 local-DNS and remote-DNS modes are distinct. Proxy and target queries/effects keep separate original leases. Proxy input absent versus explicit empty username/password is preserved. No environment proxy is consulted. The explicit `ProxyKind` selects the configured protocol/DNS policy; endpoint scheme supplies parsing/TLS and should agree with that kind. Missing proxy ports use the explicit 1080 profile. Nonstandard conflicting proxy-URI scheme overrides are not emulated.

Retained URI/proxy/HTTP-body buffers are bounded and zeroizing, and URI/authentication values never appear in Debug, events, aggregate metric names or READY. External mature libraries may create transient parsed URL/header buffers; verified wiping of those library temporaries is not claimed. Userinfo credentials are not persisted into learned history; configured URLs and proxy authentication are not serialized as learned metadata.

## HELLO storage and publication

A fully received body is still untrusted. The runtime processes one bounded original inner frame per foreground step, invokes HELLO signature/expiry checking, and schedules real `hello_add` behavior: exact original peer/key iteration, stop on an observed newer verified HELLO, otherwise REPLACE STORE. It retains original scan/store ids and MQ epochs. A scan result from a retired MQ cannot authorize STORE on a replacement MQ. Only raw STORE_RESULT1 increments stored count; scan knowledge, local cancellation, prefix uncertainty and unknown outcomes stay distinct. Empty-address HELLOs are not spuriously stored. Failed frames do not gain authority from parsing alone.

A separate credit-controlled PEERSTORE monitor feeds publication. Invalid/mismatched/expired or over-capacity records are explicitly rejected; one current full original message per verified peer is retained. Default signatures have `MetadataOnly` coverage and never prove dial-address authenticity. The current cache and its original expiries are distinct from source freshness; fresh monitor attachment requires SYNC. Publication uses exact original binary frames and the official derived `{"hellos":["gnunet://hello/..."]}` JSON representation. HTTP `Accept: application/json` is selected by the active C exact case-insensitive rule. All request paths select the hostlist, GET and OPTIONS work, upload data/other methods are refused, and CORS is present. HTTP publication is plaintext as in the active MHD flags; HTTPS bootstrap is implemented separately.

Binary and JSON bodies are shared immutable Bytes owners. Their retained Vec capacity remains charged through the last original Hyper output-buffer reference, including old revisions. Capacity rejection preserves the previous unexpired publication. Accepted sources are bounded globally/per IP, canonicalized through shared native stream initialization, and have original finite header/body/write lifetimes. Publication/signed expiry tightens source leases; IO checks them before native read/write. No expired data is newly written under a fabricated current lease. Connection:close is explicit; keepalive is not a required component protocol. An empty synchronized cache produces a valid empty hostlist rather than the C empty-set refusal bug.

## Advertisements, counters, history

Only current CORE inbound full messages can create learned tests. Original CORE epoch and peer-generation tokens accompany a test even if that source later retires. Persisted history restores neither of them. New current links get at most one advertisement intent, using the public message160 producer and MQ preference80. Queueing/local whole writes/partial outcomes and remote processing are separate; old sends are never rebound/replayed on a new peer generation. Self-loopback links are excluded from bootstrap connection count and advertising.

The STATISTICS MQ receives bounded coalesced absolute local counter snapshots. Queued versus complete local SET writes and retired prefixes are explicit; no SET/persistence ACK is fabricated. A replacement stream receives a fresh snapshot of present counters, not a retired immutable request. Per-URI metric names are deliberately omitted to avoid publishing credentials/path/query data. Backoff/learned metadata recovery comes from this Rust process's qualified store rather than importing C files or treating a stat write as durable.

`Durable::recover(actual_store, actual_loaded, core, body_cap, entry_cap)` checks the original Namespace::Hostlist Store/Loaded generation pair before any worker starts. Existing marked generation0/missing canonical history and positive-generation empty bodies are refused. A truly new root synchronously commits its legal initial URL/quality/retry business snapshot under the same writer lease, checks the namespace/generation1 receipt, then starts exactly one worker. No await/cancellation split can publish READY before this initial commit. The Loaded diagnostic preserves the original loaded generation and separately reports an initial committed generation; worker admission is never fabricated for the synchronous bootstrap. It parses bounded URL/quality/retry history, validates URL grammar, rejects credential-bearing history, and restores no live download, verification result, CORE/HTTP epoch or operation. Actual single-worker Job/expected generation/Committed receipt match before `saved` changes. First unknown/failed persistence latches write admission; original cause and temporary cleanup errors remain available. The final created-directory bit is retained. Other snapshot namespaces retain their separately owned recovery guards.

## Limitations

Native mixed-C interoperability, bootstrap effectiveness, HTTP proxy/TLS behavior, persistence recovery under faults and full-node integration remain unproved. No stopped DHT, UDP crypto/collision or GNS recovery implementation was accessed or resumed.

The mature HTTP transport is the independent gnunet-http-host foundation, with GET/HEAD and bounded SOAP POST and no HOSTLIST/NAT business dependency. This component retains a thin original Fetch/Job GET adapter with its official1000-byte URI cap. Public HTTP serving reuses the foundation native byte/expiry guards. NAT uses the provider independently; SOAP POST never automatically redirects or replays. Request owner queueing, dispatch invocation, stream-write attempts, TLS plaintext acceptance, native socket bytes and complete HTTP response remain distinct facts. No one of them is a whole-write or remote-processing ACK. HTTP/2, non-UTF8/zone-id URL extensions rejected by url2.5.8, and exotic undocumented libcurl proxy-URI override behavior are outside the selected explicit HTTP/1/configured-proxy profile. Local FQDN discovery and qualified filesystem startup use the existing native startup ports; their OS calls are not falsely claimed canceled by an async network timer.

The native SDK uses the `official-hostlist` feature; the pure `hostlist` and
`hostlist-alloc` interfaces remain separate from HTTP/runtime ownership.
