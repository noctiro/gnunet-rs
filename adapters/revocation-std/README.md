# REVOCATION service runtime

`gnunet-revocation-host` composes accepted SERVICE MQs, the shared CORE and SETU native clients, one explicit verification worker, and one explicit fenced snapshot worker. It is Unix host code; pure certificates/PoW/IPC remain in `gnunet-revocation`. No production libgnunet FFI, hidden Resolver, implicit runtime, or background network task is introduced.

The caller opens a new marked `Namespace::Revocation` store and passes its actual `Loaded` receipt, external CORE/SETU allocation domains, fixed endpoint sources, the same `Arc<dyn RuntimeClock>`, service ACL/Unix credential policy, resource limits, and explicit native ABI profiles to `Server::recover`. That method creates exactly two named workers. `Server::admit` is available for actual `AcceptedConnection` composition; `poll`/`drive` accept canonical listeners. Observations describe original admissions, bytes, statuses, and commits. `shutdown` physically closes all application/CORE/SETU MQs first, then drains the original admitted file job and joins both original workers; first service error, independent storage/verifier/network errors and counters remain available. Drop also closes sources before any worker join.

An unknown certificate is checked in the one CPU worker with its original local request/source, logical deadline, and native hard bound. The worker owns one reusable1MiB scratch and one bounded command/result slot. Signature and nonce-order validation precede32 hashes; cancellation, source retirement, clock error and original deadlines are checked between every hash. CPU/OS progress is required to finish a hash/join; no hard wall-clock preemption of a native hash or filesystem syscall is claimed. No main-reactor loop runs32 hashes. Actual `CheckedCertificate` is a private production receipt, never constructed from a persisted score or mock.

Only a matching original snapshot-worker `Committed` receipt advances the live inventory and permits a new REVOKE0 response. Local IPC writing, CORE payload completion, SETU CREATE/ADD/CANCEL writes, or a queued file job are not durable acceptance. Invalid signature/work/lifetime drops the original application MQ as pinned C does; a known nonpublication store failure produces REVOKE1 when its original MQ is still live. Uncertain publication latches admission and physically closes MQs without false success/failure. An admitted disk transaction may complete after its requesting MQ expires or closes; its result is retained and never replayed.

The inner Rust image stores each complete372-byte public certificate plus its original admission score/time/policy, behind the shared marked, locked, checksummed, generation-fenced snapshot format. Only actual `Loaded` can restore this inventory. Restored durable accepted knowledge is not fresh PoW checking. Accepted keys stay revoked after their original admission lifetime; querying does not resurrect them. Already-known duplicate REVOKE returns0 without rechecking a replacement proof, matching active C behavior. New external certificates still require current policy/time checking. No C database, unmarked directory, or foreign namespace is adopted. Default8192 permanent facts fit the4MiB image; construction rejects configuration whose declared row capacity cannot fit the image. A staged mutation temporarily holds a second bounded fact vector and one bounded serialized body. A sorted index of one machine word per fact supports binary queries without copying public keys. Recovery sorts indices and checks adjacent duplicates in O(n log n), while publication inserts one index into reserved capacity. The fact vector stays append-only so existing CORE/SETU cursors remain valid.

New durable public inventory drives full380-byte CORE REVOKE flood messages to announced peers, and type12 SETU elements under SHA512(`revocation-set-union-application-id`, no NUL). Appending knowledge advances a peer cursor only after the original full CORE payload write; that write proves no remote delivery. Reconnection begins a distinct knowledge intent from durable inventory, after original CORE sends/notices retire. No application mutation is replayed. The initial initiator comparison uses explicit native word order matching pinned C's reverse32-bit `GNUNET_CRYPTO_hash_cmp` profile. Two bounded union slots per peer also accept simultaneous operations. Periodic new reconciliations recover missed unadmitted candidates.

SETU sets and listeners own separate MQs. A lost set is physically closed and its original local debts consumed before a fresh allocation reconstructs elements from durable inventory. An expired listener closes its original suggestions before a fresh listener allocation. No incoming ID is rebound. Each operation and partial send has an original hard deadline and bounded retirement grace; delayed polling cannot renew hard+grace. CREATE/ADD are local writes only; union DONE/FAILURE come only from result statuses. Every returned element must be kind12 with a full valid REVOKE frame before candidate admission. Full snapshot rebuild precedes outgoing/incoming reconciliation. Original source epochs/operation IDs remain on candidates and diagnostics.

The network candidate FIFO is bounded (default64). While verifier/disk work is busy, existing bounded unverified candidates retain original deadlines. Further unadmitted network certificates can be dropped with explicit capacity counters and no ACK; later fresh reconciliation can offer still-missing inventory again. Complete application RX is instead retained under capacity while existing output drains. Peer rows, CORE sends, SETU operations/suggestions, frames, retained bytes, and both worker channels are independently bounded. This is a finite local service, not an assertion of reliable remote delivery, peer underlay readiness, or a full GNUnet node.

Pinned C has externally relevant defects that are not copied into private Rust storage: `publicize_rm` persists only the8-byte header then recovery reads a proof beyond it, and its SETU consumer expects8 bytes although its producer adds the full message. Rust persists/consumes the complete original certificate. The official IPC/flood/SETU formats are retained; C's private corrupted storage format is not a compatibility requirement.

This handoff contains production source plus one controlled client model source, rustfmt parsed only. Real crypto/store/crash recovery and mixed-peer service interoperability remain unqualified. Statistics-daemon export and a legacy C-database migration are not provided; diagnostic counters are available and migration is intentionally excluded.

Central integration adds `Loaded::created_directory()` from the directory-creation result. Fresh inventory is actually committed as an empty canonical image before the owner is published; a previously marked directory with no canonical image fails closed. The CORE native class representation is supplied with `Sources::core_order`.
