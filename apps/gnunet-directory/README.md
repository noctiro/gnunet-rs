# Ordinary `gnunet-directory`

Package `gnunet-directory-command` provides `gnunet-directory [OPTIONS] FILE...`, an offline consumer for existing plaintext GNUnet directory artifacts, including downloaded `.gnd` files. It reads the exact local files directly. It does not require a repository or CHK, import/publish/download content, start a service, load an extractor, or create a background worker.

Normal PROGRAM supplies `-c/-L/-l`, help/version, selected native configuration and logging. Every non-option argument is one selected input. No filenames is an error. The current Unix profile opens each input as an ordinary regular file (including a symlink that resolves to that original file) with nonblocking/CLOEXEC flags. FD/path device, inode, length, mode, mtime and ctime are checked throughout. Original extent is fixed at open. Early EOF, growth, replacement or mutation remains a source failure, even if a valid prefix was already shown. No identity or authentication follows from parsing public artifact syntax.

The existing core `directory::Parser` receives contiguous `Segment`s with its exact offset, the original final extent, and only the not-yet-consumed bytes of a fixed 32 KiB read buffer. Events and NeedPlain may consume zero bytes and do not trigger another read. Unconsumed tails stay in the same buffer. After the final event an empty segment is still fed to obtain Complete/Partial/Truncated; a declared final extent alone is never an EOF receipt. A Complete result is followed by original FD EOF and snapshot checks before the complete marker is printed. Strict metadata/URI validation is selected; Partial, malformed input, missing root, truncated fields and resource refusal never become complete success. Reference-compatible noncanonical padding bytes remain allowed under the existing default policy.

Each root and entry is displayed, including its filename (when present), exact URI, and every accepted metadata item in wire order. Metadata rows include numeric type, format, plugin, MIME and text value; no libextractor name/provider is needed. UTF8 text is printed with reversible control/quote/backslash escapes and printable Unicode; other byte strings use explicit byte escapes. Only the required last text terminator is omitted; an interior NUL remains visible. Unknown type numbers remain displayable. Binary values report their length. Type174 embedded full-data values report length and remain explicitly unverified. No embedded bytes are executed, extracted, or claimed to match a CHK. Display order is original wire order rather than the C metadata Set's duplicate/sort transformation.

Working memory is bounded by the selected record/metadata policies, not by retaining the whole directory or its entry list: one 32 KiB input buffer, one reusable record carry arena, one metadata plain arena that grows only for a NeedPlain, reusable Inflate state, and small text-escape buffers. Carry starts empty and grows only after an input file actually opens, to the smaller of RECORD_BYTES and that original file's extent (at least the 12-byte header). Already longer arenas are reused without shrinking or resetting them; missing files allocate no carry and small files do not unconditionally touch 2 MiB. No list of entries/results or complete artifact is collected. Total extent and entry-count defaults are not the core's former 64 MiB/4096 caps; checked u64 work and platform usize entry representation remain bounds. Per-record policy defaults to existing core values and is explicitly adjustable in `[directory-rust]`:

- `RECORD_BYTES` (default 2097152): upper bound on retained URI/framing/coded metadata for one record; carry grows lazily using each actually opened file's original extent and is reused across files.
- `CODED_METADATA_BYTES` (default 1048576), `PLAIN_METADATA_BYTES` (default 8388608), `METADATA_ITEMS` (default 4096): the existing decoder's explicit resource policy. Their numeric bounds must fit original u32 fields.
- `URI_BYTES` (default 16384): existing URI parser work/identifier bound.
- `TOTAL_TIMEOUT`: optional whole-operation duration.

Limits constrain untrusted records and allocation, not a new artifact format. Increasing them may require more memory; allocation errors remain failures. No large file is read into memory merely for display.

`--timeout DURATION` overrides the configured optional whole bound. Zero selects configuration; final zero/FOREVER is unbounded. One canonical/native target is captured before input allocation/open and never renewed for another file, event, retry or output write. Actual signal streams and original parent control handle SIGINT/TERM; parent EOF does not fabricate cancellation. Real work yields cooperatively between bounded units and after parser progress, including final events. A yield is not a guarantee that every pending OS event has already been delivered. Filesystem, stdout, URI verification and metadata inflation remain synchronous native operations and cannot be force-preempted inside a call.

Every positive input read, parser consumption and accepted stdout write is accounted before a later error. `files_validated` means Parser Complete plus EOF/snapshot checks; `files_complete` additionally means the file's completion display returned. Output byte counts are bytes accepted by the stdout writer, not a remote reader's acknowledgement. Per-file syntax/source failures are logged and the next selected file is attempted; original stop, Logger or stdout failure ends further admission. The first typed file error, additional failure count, terminal stop and independent final stdout-flush failure remain separate. Already displayed valid prefixes are not erased or replayed. A failure in any selected file makes the final process exit nonzero. No C bug that prints an invalid directory while returning0 is copied.
